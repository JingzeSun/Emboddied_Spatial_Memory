\section{Zero-training LLM operator}
\label{app:llm}
We asked whether a frozen LLM, given the same sealed feature tables as text, can choose the operations without training.
The model was DeepSeek-V4.1-Flash (API alias \texttt{deepseek-flash}, accessed 2026-10-06, thinking enabled, other parameters at the provider's defaults).
Each frame takes up to two calls: one table of recalled pairs and birth options, answered by one choice per fragment and turned into costs for the same solver; then, after the solve, one table of judgeable entities, answered by \op{RETRACT} or \op{NOOP} for each (skipped in frames without judgeable entities).
The instructions contain only the task, the column definitions and a synthetic format example.
A frame took about 16k reasoning tokens with instance masks and 37k with SAM~2.1 masks; this episode cost 19.26 USD on both front ends (plus a 6.08 USD pilot on 200 frames of a training episode), and the originally registered list of 15 episodes per front end was estimated at about 250 USD off-peak to 500 USD at peak, the longest episode alone taking several days. We therefore ran one validation episode per front end, fixed before any call by a registered draw (ascending SHA-256 of a salt and the episode identifier; the original list of 15 candidates was written before the run and is kept in the repository).
The episode (430 frames) has no identity, retrieval, residual or recovery events, so only node metrics are compared.
Invalid answers fell back to a default for at most 0.93\% of calls.
On this episode the operator reached node F1 0.696 with instance masks and 0.434 with SAM~2.1 masks (F1$_\mathrm{IoU}$ 0.376 and 0.209), and almost all of its retractions were wrong (false-retract rate 0.976 and 0.982).

\section{Reproducibility}
\label{app:repro}
Every table in this paper is generated by \texttt{paper/tools/make\_tables.py} from committed exports; the paper index (\texttt{results/vsmt\_lean\_s3\_06\_paper\_index\_154043e.json}) maps each table to its file, field, command and commit.
The statistics can be recomputed from the committed merged audits with the frozen code, and a read-only re-run reproduced them value for value (\texttt{ops/vsmt/s3\_06\_reanalysis.py}).
Learned weights are bit-identical for the same commit and thread count on the hardware we verified; audits are deterministic; the generator reproduces episode structure, not bytes; LLM answers are archived and replayed byte for byte, while the API itself is not reproducible.
