# CTL 首轮开发实验（非正式 M1）

定位：D-027 首轮开发实验的配置/方法合同；其既有结果快照为 DEVELOPMENT_RESULTS.md，之后的实验和普通进展统一追加 [EXECUTE.md](../../EXECUTE.md)，不自动新建结果报告。本页默认参数是助手为低成本开发选择，不代表研究者已冻结正式实验。

白话：先用一个只有三个位置的小世界，检查“真的改几个世界副本，再拿后续证据教网络选择”的链路能不能学起来。它不是完整机器人视觉实验，更不能仅凭高准确率判断顶刊创新成立。

## 问题、输入和输出

- 空间世界：两个可能放对象的位置，加一个受保护的背景位置。输入旧世界、t=1 的局部历史、t=2 当前区域和位置；输出 BIND/BIRTH/RELINK 的概率。例如新位置看到相同外观物体，旧位置仍有物体支持 BIRTH，旧位置已经空了支持 RELINK。
- Synthetic latent（合成表征）：用四维随机外观向量代替视觉特征。不是 DINO 特征，也不声称学会物体身份。
- Analytic projector（解析投影）：把世界的物体数量和外观加和排进三个位置，再按相机参数交换两个位置。输入执行后世界和视角，输出观测向量；例如换方向后左右交换。它是可控玩具投影，不是 Projective Node Orbit，不验证 SE(3) 等变性。
- 候选：固定生成 BIND、BIRTH、RELINK，均从同一未修改 base 用已有 executor 真正执行；只测试三个事务的学习，不覆盖完整事务语言。背景节点受到保护。D-027 原 run 遇非法执行会失败；LOG-005 后当前 harness 改为保留非法候选的 failure 并在 posterior 中 mask，不静默删除候选。
- Simulator truth（模拟器真值）：模拟器独立生成“谁在哪”的事实，再产生观测；不由 executor 输出倒推标签。它只对这个合成环境是真值，不是真实场景 ground truth。
- 真实执行轨迹：这里指合成环境实际采用的后续相机序列，不是机器人实采数据。H=3 是开发暂定值，未来时刻为 t=3,4,5；不含计划动作，也不对不同动作做因果推断。

## 两种歧义必须分开

每个组共享外观、噪声和相机序列，包含三个事务情形。BIRTH 与 RELINK 的旧世界和当前输入相同：

1. 可消歧组：历史见过旧位置是否空着，在线网络有条件判断。
2. 不可消歧组：历史也遮住旧位置，二者整个在线输入完全相同，却有不同未来。两者等量时，任何确定在线判断平均最多答对一半。应关注不确定性和暂缓提交，不能期待 hindsight 让网络获得不存在的信息。

分组拆分：整个组只进 train 或 validation 之一；不生成、不读取 test。所有结论仅适用于当前生成器分布，不代表跨场景泛化。

## 对照及监督

D-027 已完成 run 比较下表前四种方法，使用相同在线小型多层感知机（MLP：把已有信息转换成三种修改的概率）、初始化、批次、优化器、300 次更新和标签子集。约 25% 的训练组提供模拟器事务标签；不是无标签训练。实际比例写入 data_manifest.json。LOG-005 后当前 harness 另接入 D/F 两个接口分支，但尚未重新训练，旧结果仍是四方法结果。

| 方法 | 如何学习，白话说明 |
|---|---|
| ctl_analytic_teacher | 同一 base 的三个执行后世界预测未来，按总能量生成软教师概率；在线学生用标签交叉熵加教师 KL 学习。例：移动解释能预测旧位置空了。不是人工规则直接输出学生答案。 |
| direct_classifier | 只用同一标签子集训练事务分类。例：由历史和当前位置直接学习“移动”。不使用未来损失。 |
| direct_future_loss | 同样分类，再从共享编码预测真实后续向量，加入未来 MSE。例：学会预测旧位置空着，但不分别执行三个世界。 |
| future_no_execution | 额外训练结果评分器：修改前在线信息 + 候选类型 + 后续实际视角 → 未来向量，再比较真实未来形成教师。例：预测假如是移动会看到什么；评分器不读取执行后世界。学生训练形式与 CTL 一致。 |
| execute_current_only | 执行同一批候选，但教师删除 future 能量，只看当前兼容、修改、增长、附带损伤与非法项。例：旧位置是否真空未知时不会得到后续重访帮助。它诊断 future 是否必要，不是完整 CPMT。 |
| oracle_candidate_program | 在固定候选预算内直接选择 reference program，并用同一 executor/图指标计分。输入含只允许 oracle 使用的 reference，输出是覆盖上界。它不是在线模型，也不参与 A–C/A–E 主对比。 |

评分器只用相同有标签训练子集的实际事务—未来配对监督；候选全覆盖由生成器保证。它额外消耗一个网络和 300 次更新，参数/耗时单独记录。CTL 使用已知正确的解析投影，而这个对照要学习预测；两者结构知识不等价，所以这里的差异不能单独证明 execution 有独立价值。正式 M1 仍需 HC-005 公平性冻结。

损失白话：

- now：修改后的位置是否能容纳当前观测；不是完整视觉重建误差。
- future：执行后世界投影与后续真实向量的均方误差（MSE：每个数字差多少，平方后取平均）。
- edit / growth：修改操作数量 / 新增节点数量的代价；避免为解释一个观测无限建节点。
- collateral：受保护背景被破坏的代价；本实验合法候选不会破坏它，不能据此声称验证了抗附带损伤。
- illegal：非法执行诊断；合法候选为 0，非法则运行失败，不进入有限能量归一化。
- hindsight posterior：把低能量候选转成高概率，温度控制分布软硬。它是有建模假设的教师，不是真值。
- 交叉熵（CE）：有标签时，鼓励正确事务获得更高概率。
- KL 蒸馏：让在线概率接近教师概率；例如教师认为两种解释都可能，学生不应被迫只学一个硬标签。KL 本身不是创新。
- future auxiliary loss：通过训练期预测未来，帮助共享表征；不是在部署时提前输入未来。

## 未来隔离与决策

online_vector 仅接受声明的截至 t=2 字段；OnlineModel.forward 只接受这个向量。未来观测、真实后续视角、标签、真值与组编号不拼入在线输入。未来视角只给训练辅助头或离线教师。验证时可离线计算教师诊断，不把这些诊断返回优化器，也不用于在线决定。

最高概率至少 0.7 且前两名差至少 0.15 才 COMMIT，否则 QUARANTINE。白话：把拿不准的答案暂时保留，不强行改长期档案。本轮只测 gate 输出，不执行连续 pending 检索、延迟解歧或长期自滚动。因此不把暂缓率当成完整记忆系统效果。

开发默认温度 0.06、edit/growth 权重均 0.005。D-027 原 run 曾保留 BIND 与同位置的冗余 RELINK，暴露了教师偏软问题；LOG-005 按既有事务语义落实后，当前 executor 会把“不改变 target 的 RELINK”判为非法，并保留失败记录。旧输出不回写，不能把修正后的行为冒充原 run 已有结果。

## 指标解释

输入均为 validation 的在线预测和独立模拟器参考：

- accuracy / identifiable_accuracy / indistinguishable_accuracy：全部 / 有信息可判断 / 整个输入一样的歧义样本准确率。例如歧义对答对一半并非网络坏了。不是完整世界正确率。
- observable_information_accuracy_ceiling：由等量不可区分配对推出的总体上限，不是训练结果。
- initial_accuracy：相同初始化但尚未训练的准确率，用于确认真的发生学习。
- commit_coverage / committed_accuracy：多少样本敢提交，以及提交的答对多少；要一起看，不能靠全部暂缓伪造可靠性。
- indistinguishable_mean_confidence / quarantine_rate：不可区分时是否过度自信、是否暂缓。
- NLL（负对数似然）/ Brier：概率预测质量；前者惩罚给真答案很低概率，后者比较整组三类概率与真标签的平方差。不是单独的校准误差指标。
- teacher_accuracy / teacher_correct_student_wrong：教师选对多少，以及教师对而学生错多少，帮助区分教师错误与学生学不下来。B/C 的这两个字段只是解析教师的参考诊断，B/C 不受它监督。
- toy_location_fact_error：执行学生最高分事务后，身份—位置事实不一致的数量；toy_excess_node_count 是多出的物体数。只测单次修改，不是长期污染、完整图等价或候选版本历史正确率。
- peak_allocated_mb：PyTorch 张量峰值显存，不含全部驱动/桌面占用。seconds 是本机运行耗时，不是机器人实时延迟。

## 运行与审计

从项目目录执行：

~~~powershell
python scripts/run_ctl_dev.py --dry-run
python -m unittest discover -s tests -v
python scripts/run_ctl_dev.py --config configs/ctl_dev.json
~~~

需要现有 NumPy、PyTorch；默认 CUDA，CPU 调试需在独立配置显式选 cpu。dry-run 只核对配置和设备，不证明训练已经成功。

D-027 原 run 使用 train=384 组/1152 例，validation=128 组/384 例；种子 7/19/31，共 12 个学生训练和 3 个结果评分器训练。固定最后一步 checkpoint，不挑最好的验证 checkpoint；无 test，也不进行验证结果驱动的超参搜索。三个种子的均值/标准差只反映优化随机性，数据种子固定，不能写成跨数据集置信区间。当前六方法 harness 若运行必须产生新 run ID，不能覆盖或重命名旧结果。

每次运行创建新的 outputs/ctl_dev/ 目录，保存配置、数据和代码哈希、源代码快照、硬件/环境、逐候选能量和执行后世界、逐例概率/错误/提交状态、训练轨迹、权重、汇总与失败。学生部署输入单独存 online.jsonl；training_arrays 和 audit 文件含未来，仅供离线训练/审计，禁止当作部署输入。

## 不得得出的结论

本轮可以验证训练链路和信息边界；不能关闭正式 M1、证明相对强对照的创新、证明无标签学习、证明 PNO 有效或长期空间记忆改善。正式 M1 的 pre-test lock candidate 已单列在 [硬条件实验](HARD_CONDITION_EXPERIMENT.md)，在研究者接受及实现验证前仍不算冻结。开发结果不支持原假设时如实记载，不靠扩大模型或增加任务寻找正结果。
