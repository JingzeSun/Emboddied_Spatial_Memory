# M2 设计草案：强视觉前端与证据充分的记忆修订

状态：**proposed / planned，尚未冻结、实现或验证本文件所述完整 M2 系统。**

本文件按用户要求独立保存 M2 的架构建议、模型选择依据和误差诊断，属于设计材料，不维护当前阶段指针或实验结果。当前阶段与推进条件见 [M1 收口流程](M1_V2_CLOSEOUT_FLOW.md)，实际结果只写 [EXECUTE.md](../../EXECUTE.md)。本文件不改变活动 M1 配置、预算、通过门或 test 封存；M1 正式支持继续后才能实施 M2。重要方法或预算变更被接受时，再追加 [DECISIONS.md](../../docs/DECISIONS.md) 并冻结对应合同与机器配置。

## 1. M2 要回答什么

**建议方向：强预训练视觉前端＋读取充分证据的专用修订模型。先确保模型看见需要的信息，再依据误差诊断决定容量。**

Counterfactual Projective Memory Transactions（CPMT，反事实投影记忆事务）是完整系统；Counterfactual Transaction Learning（CTL，反事实事务学习）是核心学习机制。M2 要检验：在固定感知前端下，从真实执行后的候选世界形成的监督，能否比直接未来辅助损失和无执行未来评分器更可靠地学习连续世界记忆修订。

白话：输入是旧世界记忆、当前视觉证据，以及训练期随后实际得到的观测；输出是只看截至当前信息的在线修订模型及其连续记忆表现。例如机器人先把两把相似椅子记成同一个对象，后来能否依据新视角正确拆分，并保留无关记忆。它不等于训练一个更会聊天的模型，也不等于单帧识别率提高。以上效果仍待验证。

## 3. 三层架构建议

### 3.1 冻结的预训练视觉编码器

用途：把图像转换为保留局部信息的视觉特征，减少从零学习外观的负担。输入是图像及固定区域提议，输出是区域或图像局部块的特征；深度、相机位姿、可见性和不确定性作为独立观测字段保留。例如椅子正面与背面可以提供跨视角比较的线索。它本身不决定 BIRTH、RETRACT 或其他世界事务，也不保证身份匹配正确。

- DINOv2 是便于对照既有工作的候选；DINOv3 是可在 M2 开发数据上评估的候选。
- DINOv3 官方列出的 Base 约 8600 万参数、Large 约 3 亿参数；这些是预训练视觉模型规模，不是本项目已选配置或所需训练预算。见 [官方模型列表](https://github.com/facebookresearch/dinov3#pretrained-models)。
- 比较依据应包括跨视角匹配、局部区分能力、遮挡与姿态变化下的稳定性，以及完整前端成本；不只比较通用图像分类分数或模型大小。
- 所有主机制对照共享选定的 checkpoint、预处理、区域提议、深度与位姿来源。冻结的特征可按完整前端版本缓存，但缓存不能混合不同 split 的选择信息。

**冻结视觉模型不意味着整个系统只能使用弱模型；它意味着预训练知识可用，但不是这篇论文同时优化的主变量。**

### 3.2 保留几何与证据关系的修订输入

用途：避免让评分器只凭压缩的数量摘要判断世界是否应修改。输入是当前区域、相关世界节点、局部关系和截至当前的证据历史；输出是各方法共享的结构化修订上下文。例如“椅子搬走”和“椅子被箱子遮住”需要区别旧位置是否可见、是否有可靠空缺证据，而不只是比较外观。它不等于把完整参考图、未来观测或候选执行后世界喂给在线模型。

建议保留的接口信息如下；这是设计清单，尚非冻结 schema：

| 输入部分 | 建议内容 | 作用 |
|---|---|---|
| 当前区域 | 局部特征、区域支持、深度、相机射线、位姿、可见性、可靠性 | 判断本次看到的证据是什么及是否可信 |
| 相关世界节点 | 持久身份、版本、生命周期、世界表征与证据引用 | 比较旧记忆能否解释当前观测 |
| 局部关系 | 候选涉及的节点与边、保护范围、相关但不应修改的邻域 | 区分必要修订与连带损害 |
| 有界历史 | 时间、视角、证据来源及此前提交记录 | 识别重复支持、重访和矛盾；历史窗口需另行冻结 |
| 候选程序 | 同一确定性候选器产生的事务、参数与声明代价 | 在固定修改机会中进行公平比较 |

Projective Node Orbit（PNO，投影节点轨道）负责让同一世界节点在不同视角下解释观测。输入节点的 canonical world latent、位姿和可见性，输出该视角的预测特征。例如同一把椅子换角度后仍由一个节点解释；它不等于将历次观测特征简单求平均。固定或轻量投影的具体实现与容差仍需验证，不能把输入维度扩大称作 PNO 已完成。

### 3.3 专用修订模型与容量选择

用途：从上述证据中学习比较候选。输入共享修订上下文与候选程序，输出候选分数或概率；例如比较“绑定旧椅子”和“建立新椅子”哪个更符合证据。它不生成候选，不替代确定性执行器，也不能通过增加参数弥补不可观测信息。

建议先使用能读取相关节点、区域和候选关系的专用模型；当教师较好、信息可用，而学生仍有明显拟合不足时，再登记更强的结构化 Transformer 比较。结构化 Transformer 在这里指让区域、节点、关系和候选的表示相互比较的注意力网络，而非已经选定的实现。

- 先排除输入缺失、教师错误与优化问题，再判断是否需要更多层或更宽表示。
- 主比较共享输入、架构选择规则与有限预算，记录额外训练成本；不能只扩大 CTL 模型。
- 即使教师使用未来能给出正确答案，当前信息完全相同的隐藏世界仍可能无法被在线学生区分；这不自动构成容量不足。
- M1 的解析特征接口与轻量评分网络可以作为工程参考，不要求 M2 沿用同一输入维度或权重；M2 改变模型不授权回改 M1 的正式结论。

Vision-Language Model（VLM，视觉语言模型）接收图像与文字，输出描述、问答或语义判断。例如识别画面中被搬动的对象，它不等于可靠的几何关联或版本化修订器。本草案不把大 VLM 设为默认事务决策核心；若未来确有必要，应先固定它提供什么观测、调用边界及成本，并解释如何避免把预训练推理能力的收益归给 CTL。模型输出不能充当未经核验的评测真值。

## 4. 教师、在线部署与慢速修订的边界

### 4.1 真实视觉教师接口

Hindsight teacher（事后教师）在训练时利用后来已经发生的观测比较候选世界。输入同一不可变旧世界上真实执行的候选与后续有效观测，输出候选监督分布。例如后续视角显示旧位置为空，教师据此区分移动与遮挡解释；它不是未来传感器，也不是直接读取正确事务标签的别名。

M1 的受控生成器可以登记后续参考事务并从参考世界生成解析观测；真实视频通常没有这些信息。M2 必须先确定候选分支如何推进、如何与真实局部观测比较，以及哪些信息仅供评测。若教师需要额外标注或特权状态，必须披露并纳入对照公平性与标签成本，不能称为仅靠未标注视觉序列完成。

所有候选继续从同一 immutable base 克隆并真实执行；now、future、edit、growth、collateral、illegal 分项记录。教师和在线模型的输入接口应分开，执行基础无梯度、确定性、带版本。相关约束沿用现有合同。

### 4.2 在线部署与审计分开

建议建立独立的部署调用路径：当前观测与当前记忆 → 确定性候选与静态预检 → 网络评分 → 执行选中事务 → 新版本记忆。训练或评测审计可以展开所有候选，但不能把其结果反馈给在线评分器。

白话：这个拆分解决“审计全部候选的成本被误写成单次部署成本”的问题。输入同一当前世界与候选，输出独立的部署决策和审计记录；例如网络选中 RELINK 后，部署只执行它，审计结果另行保存。它不改变教师真实执行所有候选的硬要求，也不允许把仅网络前向耗时当完整系统延迟。需要验证两条路径在相同输入、选中事务和随机性控制下的提交结果一致。

### 4.3 慢速全局协调

Global reconciliation（全局记忆协调，planned）用于修复跨对象或较长历史中的矛盾。输入截至修订时刻已收到的证据、版本历史与相关子图，输出经同一执行器检查的补偿事务。例如重访后发现两个节点实际对应同一把椅子，提交 MERGE 并修订相关关系。它不等于主动去寻找新视角、不读取修订时刻之后的未来，也不删除或回填过去犯错的记录。

建议先验收视觉在线链，再研究慢路径；触发、历史窗口、处理范围和预算均待冻结。对照应获得相同证据、触发与修订机会，并报告有无慢路径的区别，防止后台额外计算掩盖监督比较。RETRACT 关闭版本而不删除 provenance；QUARANTINE 只暂存证据，不修改 persistent world。

## 5. 准确率下降时如何定位

以下是诊断建议，不是已发现的 M2 故障或新增通过门。

| 观察到的现象 | 优先检查 | 不应直接推出 |
|---|---|---|
| 同一对象换角度就匹配失败 | 视觉特征、几何投影和可见性 | 修订网络一定太小 |
| 正确事务不在候选集合里 | 固定候选生成与覆盖 | 增大评分器就能补救 |
| 正确候选存在，教师却排错 | 执行后评分、观测可靠性和未来证据接口 | 学生容量不足 |
| 教师较好，学生连训练集都拟合不好 | 优化、模型容量、输入是否遗漏信息，以及当前可辨识性 | 直接换最大模型 |
| 训练集好，未见场景差 | 数据覆盖、过拟合与表示泛化 | 只要增加训练步数即可 |
| 单步较好，连续运行迅速恶化 | 自身错误状态覆盖、恢复机会与修订策略 | 单步准确率足以支持长期收益 |

白话：输入是逐例失败、候选覆盖、教师与学生预测，以及连续记忆轨迹；输出是下一项有针对性的诊断。例如正确候选缺失时先查候选器，不训练更大评分器。它不是看 test 后自由调参的许可，也不保证每种错误只有一个原因。

## 6. M1 通过后的建议实施顺序

下列顺序是设计建议，不是当前活动执行入口，也没有预埋服务器任务。

1. **先验收视觉与教师接口。** 固定一个具身主数据来源及场景隔离方式；检查区域、深度、位姿、可见性、节点投影和候选覆盖，明确未来证据与参考真值边界。接口可用不等于 CTL 有效。
2. **再比较单步学习与连续运行。** Teacher-forced evaluation（给定参考历史的逐步评测）输入参考旧记忆与当前观测，输出单步预测；self-rollout（使用自身记忆的连续运行）输入模型自己上一时刻提交的记忆与新观测，输出后续记忆。例如前一步误建重复节点，后者必须面对该错误继续判断，前者不承担相同累积负担。两者分别报告，不能混成一个准确率。
3. **依据诊断研究容量与慢路径。** 先解决已定位的信息或拟合瓶颈，再在事前登记的有限比较中检验模型容量与全局协调，保留同等条件下的 direct+future-loss 与 no-execution 主对照。
4. **完成表征、标签与长期效果验证。** PNO 对照包括指数移动平均（Exponential Moving Average，EMA）或均值原型及表征合同规定的消融。它们输入相同多视角观测、输出不同节点表征；例如平均椅子特征与按位姿投影的节点分别用于相同修订机制，检验收益是否仅来自表征。它们不是另一个主创新。事务标签 0%/1%/10%/100% 比较只改变人工事务标签可用量；仍使用固定语言、执行器与后续观测，不称完全无监督。随后按既定顺序进入 M3 的一个外部或现实来源验证。

正式评价应同时关注世界正确性、错误持续负担、恢复、节点增长、无关记忆损害与运行成本。具体分母、阈值、连续运行长度及统计单位须在 M2 正式协议中事前冻结，不直接搬用 M1 的量程或在 test 后调整。若 M1 正式不支持继续，执行既定停止规则，不以本文件中的模块挽救同一主张。

## 8. M1 到 M2 的接口验收（planned）

M1 当前固定候选生成器依赖执行后状态做重复检查，评测 runner 另行展开全候选，不能把它直接包装成“只执行选中事务”的部署服务。M2 的独立部署路径须先解决候选重复与失败语义，再验证同一当前输入下候选、静态 mask、选择和持久记忆结果等价；完整延迟覆盖感知、候选、评分、选中执行与提交。只计网络前向的 M1 指标不能用于机器人实时性主张。

教师接口是优先风险：M1 候选分支的后续推进使用登记参考事务，future 目标也使用参考图的结构观测；C/E 同样得到参考后续轨迹产生的关系目标。M2 不得直接把正确后续事务、完整参考图或身份标签当作传感器观测。验收需分别列出传感器证据、训练特权信息、仅评测真值，明确候选世界如何随实际观测更新并解释后续区域/深度/位姿/可见性。若仍使用特权信息，须对主对照对齐并单独报告，不能宣称无标注视觉学习。

教师分布的删项 TV 和 H3-vs-H1 对照属于分布诊断，不代表贡献比例或学生长期改善；新增软/硬教师及 horizon 学生对照必须事前登记，不能把 M1 尚未成立的性质当作 M2 前提。本文件只沉淀设计，M1 go 之前不开始扩模型或实现视觉训练。
