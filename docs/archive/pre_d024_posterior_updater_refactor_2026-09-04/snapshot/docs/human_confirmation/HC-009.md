# HC-009 — 结构候选怎样互斥、共存和分层

> 本文件已经内嵌指标解释与数字算例；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。

## 要决定什么

定义 `exclusive_group_id`、compatibility 和层级语义。否则系统可能同时相信互相矛盾的结构，或错误删除本可共存的开口。

## 固定不变量

- 互斥只在同一空间范围、时间和语义层级内成立；
- 左开口与右开口可以共存；
- “opening”可先于“door/room/corridor”确认；
- new/loop/pose 是 attachment/association 假设，不等同局部结构类型。

## 场景矩阵

| ID | 同一位置的候选 | 推荐关系 | 允许 posterior | 禁止行为 |
|---|---|---|---|---|
| S01 | 前方继续 vs 前方尽头 | mutually exclusive | 保留两者直到观测 | 同时 PROMOTE |
| S02 | 左开口 vs 右开口 | compatible | 可同时存在/确认 | 强迫二选一 |
| S03 | 左开口 vs 左侧实墙 | exclusive，同一范围 | 支持其一、拒绝另一 | 同时确认 |
| S04 | opening vs corridor | hierarchical | opening 可先确认，corridor 仍候选 | 把上位/下位当冲突 |
| S05 | opening vs doorway | hierarchical/compatible | 先 opening，后 doorway | 一次弱证据确认全部 |
| S06 | doorway vs room behind | 可共存但不同实体/层级 | door + room 候选 | 合并成一个节点 |
| S07 | corridor vs room（同一未见区域） | 通常 exclusive at semantic type | 多假设 | 同时确认同一 region |
| S08 | T-junction：左走廊 + 右走廊 + 前墙 | 左/右兼容；前进与墙互斥 | 组合结构 | 只留 top-1 |
| S09 | cross-junction：前/左/右都通 | 三者兼容 | 多 attachment | 归一化成只能一个 |
| S10 | 弯道 vs T-junction | 可先保留层级歧义 | geometry evidence 后区分 | 过早分类 |
| S11 | stairs vs ramp | 同范围功能类型 exclusive | 多假设 | 同时 PROMOTE |
| S12 | door open vs door closed | 同 identity 的 state exclusive | versioned state | 新建两个门 |
| S13 | H_new vs H_loop vs H_pose | association alternatives | 可三者共存 | 只凭外观删掉两个 |
| S14 | 两个木箱分别是两个实例 | compatible entities | 两个 confirmed object | 放进同一 exclusive group |
| S15 | B 箱是 A 箱搬迁 vs B 是新实例 | identity hypotheses exclusive | 多 identity assignment | 同时提交两种世界 |
| S16 | 左侧房间内还有走廊出口 | 不同 spatial extent，可嵌套 | room + nested corridor | 因类型不同互斥 |
| S17 | 远处两个可能开口实际对应同一模糊区域 | 暂同组，分辨后 split | 保留 region hypothesis | 立即建两个事实 |
| S18 | 两个观测候选后来发现是同一 opening | hypothesis merge，有 provenance | 合并候选 | 丢失来源 |
| S19 | 一个候选跨两个互斥组 | 必须明确 factorization | geometry/type 分组 | 全部耦合成组合爆炸 |
| S20 | unknown | 不与具体候选竞争概率质量或按规则处理 | 显式 unknown | 被迫选一个已知类型 |

## 建议的因子化

```text
空间占用：free / blocked / unknown
局部结构：straight / left / right / end / junction
语义类型：corridor / doorway / room / stairs / unknown
拓扑归属：new / loop-to-X / pose-uncertain
identity：same-object / new-object / ambiguous
```

不同因子可以组合；同一因子内再声明互斥。

## 必须由研究者选择

1. 采用单层候选还是上述 factorized groups；
2. opening、doorway、room、corridor 的层级；
3. unknown 是否占概率质量；
4. 每组最多保留多少候选及 pruning 规则；
5. 候选 merge/split 的 provenance；
6. 组合候选怎样避免指数爆炸；
7. evaluator 按完整组合还是逐因子判分。

## 推荐判题与指标

### 指标是什么意思

- **Type validity**：新增节点和边中，有多少满足类型约束。例如 chair 可以位于 room，但不能把 room 当作 chair 的部件。
- **Attachment accuracy**：新节点连接到正确父节点、锚点或旧子图的比例。
- **Hierarchy consistency**：有没有循环包含、非法跨层连接或父子类型冲突。
- **Orphan rate**：新增节点没有合法挂接点、只能停留在 unknown 区的比例。
- **Duplicate-node rate**：本应连接已有节点，却错误新建重复节点的比例。
- **Compatibility accuracy**：互斥候选没有被同时确认、可共存候选没有被错误二选一的比例。

### 数字怎么算

新增 30 个节点，其中 26 个类型合法；24 个挂到正确父节点，3 个挂错，3 个暂存 unknown；其中还有 2 个其实是旧节点的重复副本：

- Type validity = 26 / 30 = **86.7%**。
- Attachment accuracy 若 unknown 也算尚未完成，则 = 24 / 30 = **80%**。
- Orphan rate = 3 / 30 = **10%**。
- Duplicate-node rate = 2 / 30 = **6.7%**。

有 20 组互斥候选，系统有 3 组同时升级为事实；有 10 组可共存候选，系统错误删除 2 组中的一个：

- 互斥冲突率 = 3 / 20 = **15%**。
- 可共存误删率 = 2 / 10 = **20%**。

### 你需要冻结的选择

1. 节点类型、边类型和允许父子层级表。
2. exclusive、compatible 和 hierarchical ambiguity 怎样表示。
3. unknown/orphan 是否暂不计错，以及最长允许存在多久。
4. 重复节点的空间、外观和拓扑判定标准。
5. 非法类型、循环包含和互斥候选同时确认是否属于硬失败。

- 推荐 factorized exclusive groups + compatibility edges；
- oracle 硬门：S01/S03/S08/S09/S13/S14 不得违反互斥/共存规则；
- 指标：candidate recall、invalid combination rate、exclusive-group accuracy、hierarchical F1、pruning recovery；
- 不使用单一 softmax 覆盖所有可共存结构。
