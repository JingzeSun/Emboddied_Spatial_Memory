# HC-013 — 七个 Pilot 实验的硬门与指标聚合

> 本文件已经内嵌 E0～E6 的指标解释、数字算例和聚合规则；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。本文件仍按 E0–E6 做功能级 evaluation 以便定位错误，但七组都必须映射到 D-022 的同一母命题，不能解释成七个平行创新。

## 要决定什么

1. oracle module fixture 是否要求所有合同/语义硬门 100% 通过；
2. 任一禁止行为是否直接 No-Go，不能被平均分抵消；
3. 多个正确输出是否使用 acceptable set；
4. 学习指标的数值阈值如何只在 validation 冻结；
5. 模块结果和端到端结果是否分别报告；
6. 哪些失败否定整个方向，哪些只收缩单一 claim；
7. 缺失/不适用指标怎样聚合，避免选择性报告。

## 七组硬门在母命题中的角色

| 实验 | 只负责冻结什么 | 不能被误写成什么 |
|---|---|---|
| E0 | semantic/topology/version 更新的判尺可信 | 模型能力 |
| E1 | candidate status 与有限拓扑扩展可被证据纠正 | 动作预测创新 |
| E2 | append/merge/ambiguous 的拓扑身份判定 | 单独的回环系统贡献 |
| E3 | revision 证据不足时怎样补证 | 完整规划贡献 |
| E4 | candidate 何时成为/不成为 fact，版本何时生效 | 独立记忆模块 |
| E5 | affected/control/stop + typed versioned revision | 普通抗噪或融合 |
| E6 | Top-K/prompt 对 world posterior 必须 zero-delta | 检索贡献 |

最终 Go/No-Go 必须优先看 E5 的必要修改、无关保持、停止与版本，再检查 E0–E4 的前置是否可信和 E6 的边界是否守住；不能因为 E1/E3/E6 的任务分数高就宣布核心 revision 成立。

## 建议的两层 evaluation

```text
功能级：
给正确上游输入 → 单独测试一个模块 → 硬门 + 模块指标

端到端：
逐层移除 oracle → 运行完整 sequence → 累计正确性、成本与失败类型
```

任何功能级硬门失败时，不得用端到端任务偶然成功掩盖。

## 通用输出记录

每次评价至少保存：

- `eligible: true/false`：该样例是否满足当前 HC 语义；
- `hard_gate_results`：每个禁止行为是否出现；
- `acceptable_outputs`：允许答案或不变量集合；
- `actual_output` 与逐字段 diff；
- `soft_metrics`、置信区间和样例数量；
- `failure_type`、证据和 decision_ids；
- oracle/estimated sensor 标识。

## E0 — 合同、执行器与评分器

**功能**：确认输入合同可表达、合法更新可执行、非法更新会原子拒绝、evaluator 能发现人工植入错误。

**固定输入**：人工 initial belief、oracle hypothesis/update、acceptable posterior。

**被测输出**：validated posterior、version/provenance、evaluator verdict。

**硬门建议**：合法 oracle fixture 全通过；任何非法引用、candidate→confirmed 泄漏、半提交、版本环或漏检人工错误均 No-Go。

| ID | 场景 | 期望 | 一票否决 |
|---|---|---|---|
| E0-S01 | 空图初始化后 ADD 一个合法 confirmed node | 版本 0→1，provenance 完整 | 无版本/证据 |
| E0-S02 | 合法 PROPOSE candidate | 只进 HypothesisSet | 进入 ConfirmedGraph |
| E0-S03 | 合法 PROMOTE | 候选历史保留、事实版本建立 | 删除候选来源 |
| E0-S04 | 合法 REJECT | rejection reason/version 保留 | 物理删除无历史 |
| E0-S05 | 非法 node ID | 整组拒绝 | 部分提交 |
| E0-S06 | 非法 relation endpoint | 整组拒绝 | 悬空边进入图 |
| E0-S07 | 版本 base 不匹配 | stale-write rejection | 覆盖新版本 |
| E0-S08 | 制造版本环 | validator 拒绝 | 环被接受 |
| E0-S09 | operator 参数类型错误 | schema reject | 隐式强转执行 |
| E0-S10 | affected 与 control 重叠冲突 | reject/明确规则 | 同一事实改又保留 |
| E0-S11 | 两个等价合法操作序列 | 两者均通过 acceptable set | exact-match 误杀 |
| E0-S12 | 多改 plant 再改回 | evaluator 发现 collateral/version pollution | 只看最终图判对 |
| E0-S13 | 人工植入漏改箱子 | propagation metric 恶化 | evaluator 漏检 |
| E0-S14 | query 改变 world graph | zero-delta gate 失败 | 因目标正确而放过 |
| E0-S15 | 缺失 decision_ids | run/fixture 不合格 | 结果仍进入汇总 |

**模块指标**：contract pass、illegal rejection、atomicity、version validity、provenance completeness、error-injection detection。

## E1 — 动作条件结构预测与观测纠正

**功能**：E1-A 测 `B_t + action → expected visibility/candidates`；E1-B 固定正确候选后，测观测能否 support/reject/propose。两个分数分开。

**固定输入**

- E1-A：oracle current belief、planned/executed action、pose uncertainty；
- E1-B：oracle candidate set、oracle-aligned observation、visibility/reliability。

**被测输出**

- E1-A：candidate graph、expected-visible mask、unknown region；
- E1-B：support/reject/retain/propose transition，不直接改 confirmed facts。

**硬门建议**：预测不得写 ConfirmedGraph；只确认实际可见范围；blocked/unknown pose 不得按 nominal action 扩图。

| ID | 场景 | 允许输出 | 一票否决 |
|---|---|---|---|
| E1-S01 | 直走廊，计划前进 | H_forward + expected visible strip | 直接确认无限走廊 |
| E1-S02 | 前进后看到连续自由空间 | support H_forward，局部可见区进入后续确认 | 更远未见区变事实 |
| E1-S03 | 前墙+左侧可靠开口 | reject H_forward，propose H_left/opening | 仍保留直行高置信事实 |
| E1-S04 | 前墙+左侧深度缺失 | reject/retain 直行依据证据；左侧 quarantine | 确认左走廊 |
| E1-S05 | 左侧只见门缝 | propose opening，类型 unknown | 直接 corridor |
| E1-S06 | T junction | 可同时 propose left/right，reject forward | 只保留 top-1 |
| E1-S07 | cross junction | forward/left/right compatible candidates | softmax 强制唯一 |
| E1-S08 | 重复帧、pose 未变化 | 不增加长度/节点 | greedy append |
| E1-S09 | executed action 被阻止 | prior/posterior 按 blocked 处理 | 按 planned distance 扩图 |
| E1-S10 | partial forward | 只预测/确认 partial transition 覆盖区 | 二元全程扩图 |
| E1-S11 | pose covariance 高 | candidates 低置信或 quarantine | 高置信 attachment |
| E1-S12 | RGB 开口、depth 墙体冲突 | sensor ambiguity | 强制扩图 |
| E1-S13 | action=turn-left，旧右侧离开 FOV | visibility change + new expected region | 关闭旧右侧事实 |
| E1-S14 | 纯语言 prior “走廊常继续” | weak candidate | confirmed fact |
| E1-S15 | observation 出现预测外新门 | propose unexpected candidate | 因 prior 未包含而忽略 |
| E1-S16 | 候选被墙反证后下一帧再次噪声支持 | 保留 evidence history，按可靠性处理 | 来回覆盖无版本 |

**模块指标**：candidate recall@k、false candidate rate、expected-visible accuracy、transition accuracy、false expansion、unknown integrity、calibration。

## E2 — 新区域、回环与定位不确定

**功能**：固定局部结构识别结果，只测试 Place/Chart association 与 append/merge/abstain 决策。

**固定输入**：oracle local structure、历史地图、pose/odometry、appearance/geometry/topology evidence。

**被测输出**：H_new、H_loop(X)、H_pose 的分数/状态、attachment proposal 和验证需求。

**硬门建议**：冲突或多历史匹配时不得不可逆 append/merge；loop 必须引用具体旧 Place。

| ID | 场景 | 允许输出 | 一票否决 |
|---|---|---|---|
| E2-S01 | 独特地标+几何+拓扑匹配 X | loop(X) | append duplicate |
| E2-S02 | 外观相似但新连接与 X 不兼容 | new | appearance-only merge |
| E2-S03 | pose 连续、无 loop geometry | new candidate | 无证据 loop |
| E2-S04 | odometry 漂移且证据冲突 | new/loop/pose 多假设 | top-1 commit |
| E2-S05 | wheel slip，实际同地 | pose/repeated observation | append |
| E2-S06 | 真 loop 但可移动箱子变化 | loop + dynamic revision candidate | 因箱子变化判 new |
| E2-S07 | 完全对称走廊 | 多假设+active target | 强 merge |
| E2-S08 | 一部分旧区域、一部分新区域 | revisit + expansion 组合 | 整体二选一 |
| E2-S09 | 几何匹配但方向/拓扑不可能 | reject loop/quarantine | 穿墙 merge |
| E2-S10 | 两个历史 Place 等价匹配 | loop(X)/loop(Y) | 任意唯一 ID |
| E2-S11 | 楼层不同但视觉相同 | new，利用高度/transition | 跨楼层 merge |
| E2-S12 | elevator/teleport transition | reset/transition hypothesis | 普通连续 append |
| E2-S13 | 历史地图可能错误 | loop + map-revision hypothesis | 把 map 当绝对真值 |
| E2-S14 | 主动回看出现唯一地标 | promote loop target | 永久不决 |
| E2-S15 | localization lost | H_pose + safe fallback | append/merge |

**模块指标**：new/loop/pose classification、false append、false merge、abstention quality、target-place recall、recovery steps。

## E3 — 主动取证动作

**功能**：固定正确 belief/hypotheses 和动作后果模型，只测试安全过滤、action utility 与 acceptable action set。

**固定输入**：oracle candidate probabilities、每个动作的可能观测、任务目标、风险和成本。

**被测输出**：允许/拒绝动作、utility decomposition、验证目标与停止决定。

**硬门建议**：风险违规为 0；无任务相关歧义时停止验证；action decision 对 world graph zero-delta。

| ID | 场景 | 允许输出 | 一票否决 |
|---|---|---|---|
| E3-S01 | left-look 低成本区分 corridor/room | left-look | 忽略明显判别动作 |
| E3-S02 | back-look 区分 loop/new | back-look/reobserve | 只走最近 frontier |
| E3-S03 | 高信息动作会碰撞 | safety reject | 信息抵消安全 |
| E3-S04 | 两动作信息相同、成本不同 | 低成本或容差集合 | 选明显高成本 |
| E3-S05 | 歧义不影响当前路线 | task action/stop verify | 无限好奇观察 |
| E3-S06 | 已充分确认 | continue task | 重复复查 |
| E3-S07 | sensor 暂失效，原地复查可恢复 | reobserve | 带故障前进 |
| E3-S08 | ask 与 move 都可消歧 | 按成本形成 acceptable set | 隐藏一种通道 |
| E3-S09 | 错箱子代价高 | clarify/verify | recency 贪心 |
| E3-S10 | deadline 紧迫 | 按冻结任务优先规则 | 永远最大信息 |
| E3-S11 | 一个动作同时区分多个候选 | 优先 joint action | 逐个低效验证 |
| E3-S12 | 观察高噪声 | 用 expected 而非理想信息 | 高估结果 |
| E3-S13 | 无安全信息动作 | stop/ask/fallback | 强制移动 |
| E3-S14 | 两动作效用在容差内 | 两者 acceptable | exact-match 唯一 |
| E3-S15 | 信息高但定位风险大 | 计入 localization risk | 只看路径长度 |

**模块指标**：oracle action-set accuracy、utility regret、information gain、steps-to-correct、cost、risk violation、over-exploration。

## E4 — 候选保留、晋升与拒绝

**功能**：固定候选和证据序列，只测试 hypothesis lifecycle，不测试 candidate generator。

**固定输入**：oracle candidate、support/contradiction evidence、独立性标签、visibility/reliability。

**被测输出**：RETAIN/PROMOTE/REJECT、confirmed extent、provenance。

**硬门建议**：prior/单次弱证据不晋升；可靠反证必须拒绝；晋升不得超过证据覆盖范围。

| ID | 场景 | 允许输出 | 一票否决 |
|---|---|---|---|
| E4-S01 | 只有模型 prior | RETAIN | PROMOTE |
| E4-S02 | 单帧局部清晰自由空间 | 局部支持/RETAIN | 无限走廊 |
| E4-S03 | 五帧同 pose 重复证据 | 相关证据，不机械累计 | 按帧数晋升 |
| E4-S04 | 三个独立视角支持 | PROMOTE 倾向 | 永久不确认 |
| E4-S05 | RGB/depth 冲突 | RETAIN/QUARANTINE | PROMOTE |
| E4-S06 | 只确认 opening，类型未决 | partial promotion | corridor/room 全确认 |
| E4-S07 | 转向后连续走廊结构 | PROMOTE observed segment | 仍只保留 opening |
| E4-S08 | 后续证明是凹槽 | REJECT passage | 候选继续有效 |
| E4-S09 | corridor/room 证据接近 | 多假设 RETAIN | top-1 PROMOTE |
| E4-S10 | attachment 与 pose 冲突 | REJECT/pose quarantine | PROMOTE |
| E4-S11 | loop 未决但局部结构明确 | 局部确认、归属保留候选 | topology 同时确认 |
| E4-S12 | 候选长期无证据 | decay/retain/expire 按冻结规则 | 自动变事实 |
| E4-S13 | 被拒候选获得新独立证据 | 新版本 reopen/propose | 删除旧反证 |
| E4-S14 | 多传感器共享同一错误 pose | 非独立，QUARANTINE | 多数投票晋升 |
| E4-S15 | 主动动作给出明确判别证据 | PROMOTE/REJECT 对应候选 | 忽略 action target |

**模块指标**：promotion precision/recall、rejection accuracy、confirmation delay、false expansion、ECE/Brier、reopen recovery。

## E5 — 真实变化的有限修订

**功能**：E5-A 固定 association/visibility 测 change type；E5-B 固定正确 change type 测 affected/control/stop 与 versioned executor。

**固定输入**

- E5-A：oracle old belief、aligned observation、identity/visibility/reliability；
- E5-B：oracle typed change seed、stored/derived relation contract、dependency graph。

**被测输出**

- E5-A：relocation/absence/occlusion/sensor-inconsistent；
- E5-B：typed delta、affected/control/stop、posterior version。

**硬门建议**：occlusion 不删除；unknown 不虚构；required relation 不漏；control mutation=0；非法/半提交=0。

| ID | 场景 | 允许输出 | 一票否决 |
|---|---|---|---|
| E5-S01 | chair 在 B 重现，A 清楚为空，同一 ID | SUPERSEDE A→B | A/B 同时当前有效 |
| E5-S02 | B 是另一把椅子 | ADD B，A 独立判断 | 合并 identity |
| E5-S03 | A 多视角可靠为空，无目的地 | INVALIDATE A，location unknown | 虚构 B |
| E5-S04 | A 被人物遮挡 | PRESERVE + visibility | INVALIDATE |
| E5-S05 | A out of FOV | PRESERVE/out_of_fov | absence |
| E5-S06 | pose/depth 冲突 | QUARANTINE | revision |
| E5-S07 | door closed→open | UPDATE_STATE，同 identity | 新建第二扇门 |
| E5-S08 | person stationary 很久 | motion state 变，ontology actor 不变 | 变 fixed structure |
| E5-S09 | cart+box 一起移动，supports 保持 | 必要位置后果+relation preserve | 只改 cart |
| E5-S10 | box 从 cart 掉落 | 关闭 supports，更新 box | supports 仍有效 |
| E5-S11 | plant 与 cart 无依赖 | plant zero-delta | 全图重算产生版本 |
| E5-S12 | hidden object inside moving container | 按 HC-003 保留 motion hypothesis/传播 | 无证据硬确认位置 |
| E5-S13 | room contains 很多对象 | 不沿 contains 全屋传播 | 修改所有对象 |
| E5-S14 | attached object 随 shelf 移动 | operator-specific propagation | 漏掉 attached object |
| E5-S15 | derived near/above 改变 | 重算，不一定 explicit delta | 当 stored 传播 |
| E5-S16 | 两个独立变化 | 分开 scope/transaction 或合法组合 | 用虚假路径连接 |
| E5-S17 | dependency cycle | reject/stop | 无限传播 |
| E5-S18 | stale base version | reject entire update | 覆盖新世界 |
| E5-S19 | 多个最小合法 scope | 接受 equivalence class | exact-match 误判 |
| E5-S20 | full-graph 得到同一最终图但多改历史 | 正确性与局部性分开；局部 claim 失败 | 只看最终图判优 |

**模块指标**：change-type F1、operator accuracy、required propagation recall、control preservation、collateral revision、stop accuracy、version/transaction validity、latency/storage。

## E6 — 任务语境与世界事实隔离

**功能**：固定完整世界图和候选对象，只测试 ActiveContext ranking、clarification 与 read/write separation。

**固定输入**：oracle box_A/box_B、关系、路线、prompt、任务代价/风险。

**被测输出**：ranked candidates、clarify/act decision、action target；world delta 必须为空。

**硬门建议**：query 前后 world graph/versions exact zero-delta；非选实例保存；高风险歧义不静默执行。

| ID | 场景 | 允许输出 | 一票否决 |
|---|---|---|---|
| E6-S01 | 右转后 B 最近；“找木箱” | B 排高，A 保留 | 删除 A |
| E6-S02 | “找刚才直走看到的” | A 排高 | recency 固定选 B |
| E6-S03 | “找门旁的”，只有 B 满足 | B | 无必要澄清 |
| E6-S04 | 两者都满足、代价近似 | acceptable set/top-k | 伪造唯一答案 |
| E6-S05 | 走错代价高 | clarify | top-1 静默执行 |
| E6-S06 | 一个候选危险 | safety filter/clarify | 为高分冒险 |
| E6-S07 | “任意一个” | 低成本候选 | 强制询问 |
| E6-S08 | “两个都找” | 两者保留并返回 | 只留 top-1 |
| E6-S09 | query 只回答位置 | read-only top-k | 为回答改图 |
| E6-S10 | query 触发抓取，重量不同 | clarify/按属性 | 忽略行动后果 |
| E6-S11 | 用户第二轮补充属性 | 重新排序 | 修改对象事实 |
| E6-S12 | identity 本身有歧义 | 暴露/先解决 identity hypotheses | referent ranking 强行 merge |
| E6-S13 | 多于两个候选 | top-k/分组/clarify | 隐藏可行候选 |
| E6-S14 | 用户无法回应且 deadline | 按冻结 fallback | 假装确定 |
| E6-S15 | prompt 前后检查世界 diff | exact zero-delta | 任何 node/edge/version 变化 |

**模块指标**：referent recall@k、accuracy@1、ranking responsiveness、clarification precision/recall、task cost、nonselected preservation、world-belief zero-delta rate。

## 端到端 Integration 场景

模块通过后才移除 oracle，运行以下组合序列。端到端错误必须回溯到最早失败模块。

| ID | 连续过程 | 最终必须满足 |
|---|---|---|
| I01 | 直走廊：propose→move→observe free→promote | 只确认可见区，版本和证据完整 |
| I02 | 预测直行→见墙/左开口→reject/propose→left-look→promote | 直行候选消失，左侧结构有限确认 |
| I03 | 重复走廊→new/loop/drift 多假设→回看地标→loop | 无 false append，验证动作成本可追溯 |
| I04 | wheel slip→pose ambiguity→relocalize | 不因 nominal action 扩图，恢复后继续 |
| I05 | 椅子 A→B→旧址可靠为空 | identity/version/scope 正确，无关事实不动 |
| I06 | 椅子被人物遮挡→人物离开→椅子重现 | 全程保持椅子事实，visibility 正确 |
| I07 | cart/box 移动→supports 保持→near 重算 | 必要传播完整，derived/stored 不混用 |
| I08 | 两木箱→prompt/路线改变→排序切换 | 两实例与世界版本始终 zero-delta |
| I09 | depth/pose 冲突→quarantine→复查恢复 | 冲突期间无 confirmed write |
| I10 | 新区域探索同时远处对象真实变化 | expansion 与 revision 分开 transaction/scope |
| I11 | loop closure 后发现旧地点结构长期改变 | place association 与 world revision 都正确 |
| I12 | 主动动作高信息但危险，选择安全次优动作 | 无风险违规，belief 最终可恢复 |

## 聚合规则候选

### E0～E6 的指标是什么意思、数字怎么算

#### E0：合同、执行器与评分器

E0 不是评价模型聪不聪明，而是检查“尺子本身准不准”。schema 解析、版本写入、禁止操作拒绝和 evaluator 手工算例更适合作为硬门槛。

准备 50 个极小 fixture，每个正确答案都能人工逐项计算。如果 49 个通过：

- E0 pass rate = 49 / 50 = **98%**。
- 这里的 98% 不代表“已经很好”，而代表评价基础设施仍有 1 个确定性错误。
- 如果后续模型实验使用这把有误的尺子，得到的分数不能作为可信结论。

需要冻结：E0 是否必须 100%；允许多个答案时 evaluator 怎样接受 acceptable set；非法输出是否直接拒绝；版本和 provenance 少一项是否失败。

#### E1：动作条件结构预测与观测纠正

核心区分是：合理预测可以作为 candidate，但无证据盲目延长不能成为 confirmed fact。

50 次结构扩展机会中，真实应该扩展 45 次。系统正确提出 40 次候选，漏掉 5 次，另在 5 个墙后场景盲目延长：

- Candidate recall = 40 / 45 = **88.9%**。
- Blind expansion rate = 5 / 50 = **10%**。

如果 40 个正确候选中只有 32 个在观测到来后正确吸收：

- Assimilation accuracy = 32 / 40 = **80%**。

需要冻结：预测的统计单位；候选允许多宽；盲目扩图是否硬失败；观测否定后多少步内必须撤回；预测正确与吸收正确是否分别过线。

#### E2：新区域、回环与定位不确定

不能只报总体 accuracy，必须分别报告 new、loop 和 drift。

三个类别 F1 分别为 0.90、0.80、0.40：

- Macro-F1 = (0.90 + 0.80 + 0.40) / 3 = **0.70**。
- 0.70 看似可用，但 drift F1 = 0.40，说明系统可能持续制造假地图。

若 30 个 loop 中 5 个被判 new，30 个 drift 中 10 个被判 new：

- False expansion events = 5 + 10 = **15**。

需要冻结：三类各自最低 precision/recall；是否用 macro-F1；false append、false merge 哪个是一票否决；多假设最长保留多久。

#### E3：主动取证动作

E3 要证明的不是“机器人动了”，而是这个动作在安全成本内减少了与任务有关的不确定性。

不主动观察时任务成功 30 / 50 = 60%；主动观察后成功 39 / 50 = 78%：

- Task success gain = 78% - 60% = **18 个百分点**。

主动观察平均多走 1.5 m、耗时 4 s，必须同时报告。若 oracle 最佳安全动作效用 0.70，系统动作效用 0.58：

- Regret = 0.70 - 0.58 = **0.12**。

需要冻结：task benefit、information gain、risk、cost 如何计算；安全硬门；最大动作预算；收益增加多少才值得多走的距离和时间。

#### E4：候选保留、晋升与拒绝

E4 同时防止两种极端：一次看见就当事实，以及永远不敢确认。

40 次候选升级中 36 次最终正确，人工标注共有 50 个真实新结构：

- Promotion precision = 36 / 40 = **90%**。
- Promotion recall = 36 / 50 = **72%**。

如果规则要求两条独立证据，但有 8 次只凭同一相机的连续相邻帧升级：

- Premature promotion events = **8**，即使其中部分后来碰巧为真，也违反晋升合同。

需要冻结：独立证据定义；晋升/降级阈值；候选最长寿命；precision 与 recall 最低线；哪些证据可以直接拒绝候选。

#### E5：真实变化的有限修订

E5 检查新证据到来后，系统是否既更新所有必要事实，又保住无关世界。

人工标注必须更新 10 项。系统正确更新 9 项，同时错误修改 2 个无关事实：

- Propagation recall = 9 / 10 = **90%**。
- Scope precision = 9 / (9 + 2) = **81.8%**。

如果错误修改包含人的 identity 或固定类型，即使平均分很高，也可按不变量硬失败。

需要冻结：每种 operator 的必要传播边；停止边界；漏传播和过传播阈值；版本链必须保存哪些证据；是否接受多个等价最小修订。

#### E6：任务语境与世界事实隔离

E6 检查最近 prompt 能否帮助选择当前目标，同时不让另一个真实实例从长期世界中消失。

100 个“两木箱”查询中，正确箱子 92 次位于 top-2，78 次排在 top-1：

- Recall@2 = 92 / 100 = **92%**。
- Top-1 accuracy = 78 / 100 = **78%**。

如果有 3 次因为最近提到右侧木箱，就把左侧木箱从世界图删除：

- Context contamination rate = 3 / 100 = **3%**。
- 这 3 次不能被 92% Recall@2 抵消；若长期事实污染被定为硬错误，E6 直接失败。

需要冻结：K；何时必须澄清；ActiveContext 有效期；排序信息能否写入 world belief；contamination 是否必须为 0。

### 七组实验怎样聚合

不要把七组分数直接求平均。建议按下面三层报告：

1. **合同与安全硬门**：E0、世界不变量、安全、测试隔离和禁止污染必须全部通过。
2. **模块门槛**：E1～E6 各自达到最低线，不能让一个强模块补偿一个失效模块。
3. **端到端结果**：在前两层通过后，再报告完整轨迹任务成功率、最终 belief 正确性、累计成本和失败类型。

数字例子：E1～E6 得分为 92、88、91、85、94、90，平均 90；但 E2 发生 3 次被禁止的“把定位漂移写成新走廊”。最终仍是 **No-Go**，不能用平均 90 抵消。

另一组结果所有硬门通过，E1～E6 最低分为 82；若事先冻结“每组至少 80”，则模块层通过。50 条完整轨迹成功 42 条：

- End-to-end success = 42 / 50 = **84%**。
- 84% 单独报告，不与模块分数继续混成一个总分。

### HC-013 最终需要你冻结的选择

1. E0 是否所有人工可计算 fixture 必须 100% 通过。
2. E1～E6 每组的主指标、最低线和 forbidden behavior。
3. 每类子场景是否必须单独过线，还是允许只看总体。
4. 多个正确答案怎样定义 acceptable set。
5. 每组至少多少 fixture、多少随机种子和多少完整轨迹。
6. 多次运行报告均值、中位数、置信区间还是最坏值。
7. Go、带条件继续和 No-Go 的组合规则。

### A. 合同与安全硬门

建议全部通过，任何一次失败直接报告 No-Go：

- candidate 写入 confirmed；
- query/ActiveContext 修改世界；
- unknown 被写成虚构事实；
- occlusion 导致事实删除；
- unsafe action 越过 hard safety；
- 非法/半提交、版本环、缺失 provenance；
- control fact 被无依据修改。

### B. 模块语义硬门

由 HC-001～HC-012 冻结后形成 per-fixture acceptable set。建议 oracle deterministic 阶段全部通过；未决语义样例标 `ineligible`，不得混入分母。

### C. 学习与性能指标

- threshold、top-k、校准门、效用权重只用 validation；
- 每个 module 单独给 macro/micro、置信区间、样例数和失败分布；
- 不用一个总平均分把 false merge、risk violation 或 world pollution 抵消；
- 若需要 summary，可用“硬门全过 + 各模块达到 validation-frozen minimum”的 conjunctive rule。

### D. 端到端指标

- final belief correctness 与 graph attachment；
- steps-to-correct-belief、task success、action/risk cost；
- cumulative false append/merge/confirmation/revision；
- earliest failure module 与 downstream consequences；
- latency、peak memory、storage growth。
