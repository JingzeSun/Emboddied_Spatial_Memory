# HC-018：收窄后 posterior-only 实验是否先行

## 为什么必须由人确认

D-022 已把唯一母命题收窄到 bounded posterior revision，但现行 `EXECUTE.md` 的 A 阶段退出门仍要求
预测、主动取证、region binding 等 HC 全部冻结。如果不改变阶段门，核心小实验仍会被已降为前置或
下游的问题阻塞；若直接跳过，又会静默改变已接受的执行合同。

本条只决定**工作顺序**，不自动接受任何语义规则，也不删除未来模块。

## 可选方案

### 选项 A：新增 posterior-only 子阶段（建议）

先冻结直接影响核心 evaluator 的：

- HC-001–005：身份、关系、传播、可靠缺失、等价最小修订；
- HC-011：ego-motion / sensor / world change 分流；
- HC-013：硬门与指标聚合；
- HC-015–017：有效时间、commit gate、基线公平性；
- HC-018 本身：阶段授权。

然后只用 oracle/fixed prediction、association、visibility 和 dependency 输入，实现 12 个 smoke fixtures、
评测器和 B0–B7 确定性基线；通过后可生成 symbolic event streams，依次训练 L0–L5 learned posterior
baselines 与 BEGR-Net。HC-006–010、HC-012、HC-014 继续 pending；不改受它们约束的 schema/config，
不宣称完成整个 A 阶段，也不做端到端世界模型。

数字例：先比较 12 个 fixture × 8 个 updater=96 次确定性运行；如果 `incident_edge_recompute`
已经在传播、control、stop、version 上与 B6 相同，就立即收缩假设，不训练。若仍有差异，再做
30k/5k/5k train/validation/ID-test 与 5k OOD symbolic transactions；这些是起始预算，不是 accepted 阈值。

### 选项 B：维持现有完整 A 阶段门

所有 HC-001–018、W0–W4 和 R1–R6 都冻结后再实现。治理最整齐，但会把 posterior 核心验证继续
绑定到非核心预测/主动取证问题，首次单人研究的前期负担很大。

### 选项 C：永久删除非 posterior 模块

彻底移除 W0–W4、主动取证与 region binding。范围最小，但后续真实观测如何生成 canonical
posterior 输入没有接口，且会废弃 D-017/D-021 的部分 accepted 决策；需要另立 superseding 决策。

## 选项 A 的边界

允许：

- 新增实验包文档、手写 fixture、evaluator、确定性 updater 与 oracle tests；
- deterministic gate 通过后训练 posterior-only learned baselines/BEGR-Net，并记录 split、seed、trial budget、loss、checkpoint 与校准；
- 在 run manifest 中明确 `upstream: oracle/fixed`；
- 用 development/validation 冻结规则，test 保持未触碰。

不允许：

- 在 HC-014 pending 时修改 region-binding 或 latent-write schema/config；
- 把 oracle 上游结果说成真实感知系统结果；
- 因 posterior pilot 开始就把完整 A 标为 completed；
- 删除未完成的 HC 或 accepted 决策历史。

## 子阶段退出门（候选）

1. 直接相关 HC 均有用户回答和对应 D 决策；
2. 12 个 smoke cases 由人复核，oracle evaluator 100% 通过硬门；
3. B0–B5、B7 能触发预期成功与故障，证明 evaluator 不是恒真；
4. B6 在至少 R2/R3/R4/R6 上面对强局部和 full-graph 反证；
5. 全部运行明确保存 `decision_ids`，状态仍标为 posterior pilot；
6. 失败结果也记录，不能据此偷看 test 或回填阈值。
7. learned 阶段只有在 deterministic falsifier 未推翻主张后启动；先跑 flat/Event-Transformer/TGN-style/full-graph，再跑 BEGR-Net。
