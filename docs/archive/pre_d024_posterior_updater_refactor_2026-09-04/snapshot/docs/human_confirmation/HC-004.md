# HC-004 — 什么证据足以判定 reliable absence

> 本文件已经内嵌指标解释与数字算例；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。

## 要决定什么

“当前没检测到”应被解释为 occluded、out_of_fov、sensor_unknown、reliably_absent，还是 removed_from_scene。可靠缺席最多关闭旧位置，不能自动编造去向。

## 固定不变量

- 没看到不等于不存在；
- 旧址不在预期视野内时不得判 reliable absence；
- removed_from_scene 比 reliably_absent 需要更强证据；
- 位置失效后去向默认 unknown。

## 必须由研究者选择

1. 旧址需要多少可见覆盖率；
2. 多帧证据的最少数量、时间跨度和独立视角定义；
3. detector/depth/pose 可靠性的最低门；
4. 单一强几何证据能否替代多帧；
5. 多久未见只能判位置失效，何时能判 removed_from_scene；
6. partially visible 如何处理；
7. 多传感器冲突时的优先级和 quarantine 条件。

## 推荐判题与指标

### 指标是什么意思

- **Absence precision**：系统宣称“物体真的不在了”的事件中，有多少确实是真实移除。它越低，越容易把遮挡误当消失。
- **Absence recall**：所有真实移除事件中，有多少最终被系统确认。
- **False absence rate**：物体仍然存在但不可见，却被系统判为消失的比例。
- **Confirmation latency**：从真实移除发生到系统形成可靠 absence 结论，经过多少帧、秒或主动观察动作。
- **Abstention rate**：系统回答 unknown、继续保留旧事实或请求再观察的比例。

### 数字怎么算

数据包含 30 次真实移除和 70 次“物体仍在但暂时被遮挡”。系统宣布 25 次“不在了”，其中 22 次是真实移除、3 次其实只是遮挡：

- Absence precision = 22 / 25 = **88%**。
- Absence recall = 22 / 30 = **73.3%**。
- False absence rate = 3 / 70 = **4.3%**。

若剩余事件中系统有 40 次回答 unknown，则还要报告 abstention rate = 40 / 100 = **40%**。否则系统可以通过永远不下结论获得很高的 absence precision。

假设 22 次正确确认分别需要 1～5 次观察，平均 2.8 次、最慢 5 次；两者都应报告，因为平均值会隐藏极慢案例。

### 你需要冻结的选择

1. reliable absence 至少需要几条相互独立的证据。
2. 什么算可靠空视野：覆盖率、深度有效率、视角和遮挡上限。
3. false absence 是否必须为 0，尤其对人、门和任务目标。
4. 最大确认延迟与最多主动观察次数。
5. unknown 的允许比例，以及超时后应保留旧事实还是标记失效。

- 推荐 reliable absence：预期区域在 FOV、无可信遮挡、pose/depth 可靠、覆盖充分且有多帧或独立证据；
- oracle 硬门：S02–S12/S16/S19/S22 不得 INVALIDATE；
- 指标：absence precision/recall、false invalidation、decision delay、occlusion preservation、unknown integrity；
- removed_from_scene 单独评测，不与 location absence 合并。
