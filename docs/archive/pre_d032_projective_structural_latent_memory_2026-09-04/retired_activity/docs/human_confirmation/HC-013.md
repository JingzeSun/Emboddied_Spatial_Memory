# HC-013：主指标、硬门与继续/停止标准

## 你必须决定什么

冻结 C1–C15 的主次层级、pilot hard gates、checkpoint 选择顺序和多个指标冲突时的 Go/No-Go 规则。公式以实验包 `CRITERIA.md` 为准。

## 已固定不变量

- 不用一个加权总分掩盖硬失败；
- oracle evaluator 必须100%；
- post-projection constraint violation 必须为0；
- test 不参与阈值、权重、提示、baseline 或 checkpoint 选择；
- 投影前后、ID/OOD、数据轨和任务错误分开报告；
- 失败与缺失样本不静默删除。

## 聚合选项

### A：硬门 + 词典序选择（推荐）

先满足 NUR/CPR/合法性，再最大化 transaction exact；并列时依次看 ECE 和效率。

### B：单一加权总分

容易排序，但可能用速度抵消世界污染；只适合附录敏感性，不作为主门。

### C：纯 Pareto，不设硬门

展示完整，但无法回答“是否继续投入”。可作图，不替代最低安全/完整性门。

## 候选 Go/No-Go 规则

| 门 | 候选阈值 | 未通过意味着什么 |
|---|---:|---|
| oracle evaluator | 100% | 判尺无效，禁止训练 |
| NUR | ≥95% | 稀疏靠漏改换性能 |
| CPR | ≥99.5% | 核心“保护无关事实”失败 |
| transaction exact | ≥80% | 单项分高但组合事务不可靠 |
| post violation | 0 | executor 合法性失败 |
| OOD relative drop | ≤20%且优于强基线 | 只记住训练噪声分布 |

以上是起点，不是 accepted 阈值。若 development/validation 显示标签上限不合理，应在看 test 前追加决策。

## 冲突判例

- M0 的 edit F1 高3点，但 CPR 从99.7%降到98%：No-Go；
- mask 缩小50%，NUR从97%降到88%：No-Go；
- NUR/CPR均过门，transaction exact从78%升到84%、ECE下降：支持继续；
- ID提升但所有 OOD 低于 FullGraph-HGT：不主张泛化；
- p95快2倍但准确/保护相同：可主张效率，不主张推断更好。
