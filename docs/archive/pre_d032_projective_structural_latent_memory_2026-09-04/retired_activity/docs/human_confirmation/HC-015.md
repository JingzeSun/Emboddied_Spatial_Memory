# HC-015：有效时间点、区间与容差

## 你必须决定什么

冻结 `τ_t` 在不同数据轨上的标签类型、精确时间容差、区间评分和迟到证据的有效时间规则。

## 已固定不变量

- `observed_at`、`received_at`、`valid_from/to`、`transaction_from/to` 分开；
- arrival time 不能冒充 world-change time；
- 3RScan 两次重扫通常只给变化区间；
- RETRACT 关闭旧事实历史，不删除；
- 不可判定时间可以输出区间/unknown，不能造精确点。

## 选项

### A：精确轨点监督 + 真实轨区间删失（推荐）

AI2-THOR 用 simulator event time；3RScan 用 `[last_support, first_contradiction]` 的 interval-censored likelihood。

### B：所有数据离散时间桶

统一实现，但可能损失模拟器精度，并掩盖真实数据区间宽度。

### C：统一用收到时间

禁止。它把通信延迟写进世界历史。

## Criteria 纵列

| Criterion | 在本 HC 中是什么意思 | 怎么算 | 数字例子 | 你要冻结什么 |
|---|---|---|---|---|
| C2 Transaction exact | 时间字段错时事务是否整体失败 | 操作/目标/时间/证据全等价 | 状态对但 valid_from 用968而非602，C2=0 | 时间是否 exact 必需字段（推荐是） |
| C8 Time MAE | 有精确事件标签时误差 | `mean(|t_hat-t|)` | 误差1/3/2秒，MAE=2秒 | 容差与单位 |
| C9 Coverage | 预测区间是否覆盖允许变化 | covered/全部 | 100例覆盖91，coverage=91% | 目标coverage，如90% |
| C9 Width | 区间是否过宽 | 平均/中位宽度 | 平均38秒；输出无限宽虽覆盖高仍失败 | 最大/相对宽度报告方式 |
| C10 Evidence F1 | 时间断点是否引用相应证据 | 证据集合F1 | last support+first contradiction都应被引用 | boundary evidence 规则 |

## 场景矩阵

| 场景 | event/arrival | 可用真值 | 推荐标签/输出 |
|---|---|---|---|
| AI2-THOR 602秒移动、968秒到达 | 602/968 | 精确event | valid_from≈602，transaction_from≈968 |
| 旧消息602秒在720秒新事实后到达 | 602/968 | 两段历史已知 | KEEP新事实，不回滚 |
| 3RScan t1仍在A、t2已在B | 两次scan | `[t1,t2]` | interval，不造中点真值 |
| 覆盖不足 | 不确定 | 无可靠断点 | QUARANTINE/unknown interval |

## 容差数字

20 Hz 模拟器中±1 step是±0.05秒；如果只按1秒桶评价，则预测602.4与602.0可同桶，但必须同时报告连续 MAE。区间 `[100,140]` 与预测 `[105,135]` 的 overlap 高，但没有覆盖整个允许区间；采用哪种 coverage 定义必须在生成 test 前固定。
