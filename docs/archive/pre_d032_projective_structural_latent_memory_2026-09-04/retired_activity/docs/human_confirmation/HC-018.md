# HC-018：第一批可执行数据从哪里开始

## 你必须决定什么

D-024/D-025 已完成方案重构，但没有决定第一批实际实现先手写 oracle cases，还是先接 AI2-THOR。该选择改变排错顺序和初始工作量，不改变研究问题。

## 选项

### A：先12个 hand-authored cases（推荐）

覆盖 S00–S11；每例包含旧图、events、oracle edit、affected/protected、valid time、evidence set、task delta 和禁止结果。先对 oracle 与故意错误验证 evaluator，再扩成每族 positive/control/counterfactual 共36例。

### B：AI2-THOR-first

先生成少量 development episodes，从 simulator state 导出事务，再回填 fixtures。更真实，但前期较难区分 adapter、visibility、标签与 evaluator 错误。

### C：最小并行

先做4个关键 hand cases，同时打通1个 AI2-THOR 房间的10–20个事务。信息更真实，但单人切换成本高。

## Criteria/退出门纵列

| Criterion/门 | 在此阶段是什么意思 | 怎么检查 | 数字例子 | 你要冻结什么 |
|---|---|---|---|---|
| oracle evaluator | 判尺能否识别正确事务 | oracle必须全通过 | 12/12=100% | 是否一票否决（推荐是） |
| deliberate corruption | 判尺能否抓到已知错误 | 每例至少漏改/越界/时间证据错 | 12×(1 oracle+3 errors)=48 inputs | 每例错误种类 |
| C1–C15 readiness | case是否提供所需标签 | 字段覆盖表 | 若没有commit probability，C12标not applicable而非0 | 第一阶段必需criteria |
| scenario coverage | 12类困难是否至少各一例 | S00–S11 presence | 12/12 families；扩展后36 cases | 先12还是36 |
| adapter smoke | 所有方法能否读写共同接口 | 只测接口/失败日志，不当性能 | 12 cases×11 adapters=132 runs | adapter齐全后何时跑 |
| test isolation | 是否只用development | manifest检查 | `split=development,test_accessed=false` | test何时生成 |

## A/B 数字工作量例

- A 最小：12 cases，48 evaluator inputs；稳定后36 cases；
- B 最小：5 rooms ×4 change scripts ×3 receive queues=60 development transactions；
- C 最小：4 hand cases + 10–20 simulator transactions。

这些是预算例，不是结果。

## 无论选什么都固定

- 不接触正式 test；
- updater 主比较固定 perception/identity/candidates/dependencies；
- 失败输入保留；
- fixture/run 保存最终 D/HC IDs；
- 第一批数据完成不等于模型已验证。
