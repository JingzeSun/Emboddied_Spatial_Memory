# HC-002：哪些事实可编辑，哪些关系只派生

## 你必须决定什么

Q02.1 已由 D-031 冻结为开放 predicate registry、schema-conditioned 共享 updater 与次级 held-out registered-predicate 泛化。现在只需冻结 MVP 的具体 stored/derived predicate 名单。只有 stored facts 才能进入 `ΔG_t`、`M_t` 和版本链；derived relation 由当前 stored facts/geometry 计算，不能重复算一次“编辑正确”。

## 已固定不变量

- 每个 stored fact 有稳定 `fact_id`、valid/transaction time 和 provenance；
- camera-relative `left/right` 不持久化；
- derived view 变化不能自动触发第二次世界写入；
- 同一事实不能既 stored 又 derived；
- 主比较共享同一 predicate registry。
- 主模型不为每个 predicate 建专属输出头；任意自然语言开放谓词不在当前范围。

## 选项

### A：最小 stored 集（推荐）

`at/contains/supports/blocks/open` stored；`near/above/left_of/right_of` 默认 derived，并显式记录 reference frame。

优点：编辑标签清楚、单人可标；缺点：复杂关系推理暂不进入主张。

### B：扩展 stored 集

将稳定的 `attached_to/connected_to` 等加入 stored。表达力更强，但每新增谓词都需冲突、时间、依赖和等价标签。

### C：观测到的关系全部持久化

不推荐。视角变化会制造大量伪编辑，并让 CPR/CER 失去解释性。

| Criterion | 在本 HC 中是什么意思 | 怎么算或判定 | 数字例子 | 你要冻结什么 |
|---|---|---|---|---|
| C1 Edit macro-F1 | 只对 stored predicate 的操作分类 | 五个 operator 分别 F1 后平均 | `at` 的 REPLACE 对、derived `near` 重算不计第二个 edit | stored predicate 清单 |
| C2 Transaction exact | 事务是否包含恰当 stored edits | 操作、目标、时间、证据整体等价 | 正确只改 `at(cart,B)`；额外写 `near(cart,door)`则不 exact | derived 写入是否一票否决（推荐是） |
