# HC-005：多个最小编辑程序怎样判为等价

## 你必须决定什么

定义 evaluator 的 equivalence class：哪些不同写法产生相同合法世界状态并可同时得分，哪些虽然最终状态相同但因多写、时间错或证据错仍应失败。

## 已固定不变量

- 历史不能删除；RETRACT 关闭有效区间；
- 写操作必须带证据和原子 transaction/version；
- equivalence 不能豁免越界写入；
- oracle 可以是 acceptable set，不强迫唯一序列化顺序。

## 选项

### A：状态 + 最小写集 + 时间 + 证据等价（推荐）

同一原子事务里的 `REPLACE(old,new)` 与 `RETRACT(old)+ASSERT(new)` 可等价；额外修改 control、时间区间不同或引用错误证据则不等价。

### B：只看最终状态

会奖励先污染再修复、多写和错误 provenance，不推荐。

### C：只接受一个 canonical program

容易评分，但把序列化选择误当科学真值，可作为实现内部规范，不能作为唯一语义判据。

## Criteria 纵列

| Criterion | 在本 HC 中是什么意思 | 怎么算 | 数字例子 | 你要冻结什么 |
|---|---|---|---|---|
| C1 Edit F1 | operator 层允许怎样映射 | 先 canonicalize 再分类 | REPLACE 可展开成 RETRACT+ASSERT 后比较 | canonicalization 规则 |
| C2 Transaction exact | 全事务是否属于 acceptable set | 等价则1，否则0 | 100例71例等价，exact=71% | exact 的必要字段 |
| C4 Mask F1 | 两个最小 affected set 是否都可接受 | 与 acceptable masks 比最大匹配 | 真集可为 `{f1,t1}` 或 `{f1,d1,t1}`，须说明 d1 是否 derived | 多解 mask 规则 |
| C5 CPR | 最终恢复但曾改 control 是否算失败 | 比较 transaction writes，不只终态 | control 被改后改回，CPR仍记失败 | 是否审计中间写（推荐是） |
| C6 CER | 多余操作是否越界 | oracle closure外写/全部写 | 4写中1越界，CER=25% | 多余 no-op write 是否计入 |
| C7 Stop exact | 多个停止边界何时等价 | acceptable boundary set | 两条同义 dependency path 可等价；多1层不等价 | path equivalence |

## 判题例子

| 输出 | 最终状态 | 时间/证据 | 写集 | 推荐判定 |

| REPLACE A→B | 对 | 对 | 最小 | 正确 |
| 同事务 RETRACT A + ASSERT B | 对 | 对 | 最小 | 与上等价 |
| ASSERT B，不关闭互斥 A | 错 | 对 | 不合法 | 错误 |
