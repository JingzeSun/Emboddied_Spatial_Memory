# HC-002 — 哪些关系存储，哪些关系派生

> 本文件已经内嵌指标解释与数字算例；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。

## 要决定什么

每个关系谓词必须指定一种语义：

- **stored**：作为版本化事实保存，变化时显式编辑；
- **derived**：由几何或其他 stored facts 计算，不单独维护版本；
- **observation-only**：只存在当前观测或查询中；
- **hybrid**：保存离散事实，同时允许从几何重算并做一致性检查。

## 固定不变量

- camera-relative left/right 不得无 reference frame 持久化；
- 同一事实不能同时被 stored edge 与 derived edge 重复计分；
- derived 关系变化不等于必须产生 ContextDelta；
- evaluator 必须知道每个谓词的来源与有效区间。

## 推荐判题与指标

### 指标是什么意思

- **Relation precision**：系统返回的关系中，有多少是真的。它反映“查到的东西有多可信”。
- **Relation recall**：人工标注存在的关系中，有多少被系统找到。它反映“漏掉了多少”。
- **Derived consistency**：临时推导关系与当前基础事实保持一致的比例。
- **Stale relation rate**：基础事实已经变化，旧派生关系却仍能被查询到的比例。
- **Storage ratio**：实际持久保存的关系数 / 如果所有关系都保存时的关系数。它只衡量存储简化，不能替代正确性。

### 数字怎么算

人工标注当前有 40 条有效关系。系统返回 38 条，其中 34 条正确：

- Relation precision = 34 / 38 = **89.5%**。
- Relation recall = 34 / 40 = **85%**。

一次位置变化使 10 条旧派生关系应当失效，但其中 2 条仍被查询到：

- Stale relation rate = 2 / 10 = **20%**。

若全部持久化需要保存 100 条关系，当前设计只保存 35 条基础关系：

- Storage ratio = 35 / 100 = **35%**。
- 只有 derived consistency 足够高且 stale relation 足够低时，35% 才能说明这种拆分有效。

### 你需要冻结的选择

1. 每个关系谓词属于 stored、derived 还是两者都不允许。
2. 几何事实、人工陈述和历史版本冲突时谁优先。
3. stale relation 是否属于硬失败，以及允许在多少毫秒或多少个 update 内完成失效。
4. 近、左侧、可达等软关系允许多大近似误差。
5. 是否以 precision、recall 分别设线，而不是只报 F1。

- 推荐规范事实：`supports/attached_to/part_of/connects/continuation_of` stored；
- `near/above/below/overlaps` derived；camera-relative directions observation-only；
- oracle 硬门：每个 predicate 只有一个 authoritative source，stored/derived 不重复计分；
- 指标：relation consistency、duplicate edit rate、stored-edge precision/recall、derived recomputation correctness。
