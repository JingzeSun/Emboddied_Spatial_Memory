# HC-018：第一批可执行数据从哪里开始

## 问题

D-024 已经授权文档主线重构，但没有决定第一批实现应先手写 oracle cases，还是先接 AI2-THOR。这个选择会改变排错顺序和前期工作量，不能由代理替你写成已接受。

## 选项 A：先 12 个 hand-authored oracle smoke cases（推荐）

先覆盖 S00–S11，每例写旧图、事件、oracle edit、affected/protected、valid time、evidence set、task delta 和禁止结果。对 oracle 与故意错误运行 evaluator；通过后再生成 symbolic 和 AI2-THOR。

数字例：12 例 × 每例 1 个 oracle + 3 个故意错误 = 48 个 evaluator inputs。若扩为每族 positive/control/counterfactual，则是 36 例。优点是几天内能发现指标或 executor 定义错误；缺点是手写案例不是具身数据，不能成为最终结果。

## 选项 B：AI2-THOR-first

先搭环境并生成少量 development episodes，从 simulator state 自动导出事务，再回填 fixtures。

数字例：5 个房间 × 4 个 change scripts × 3 个接收队列 = 60 个 development transactions。优点是早接触真实可见性和对象状态；缺点是若评分不对，很难区分 simulator adapter、标签生成、visibility 还是 updater 出错。

## 选项 C：两条最小并行

先写 4 个最关键 hand cases，同时做 1 个 AI2-THOR 房间的 10–20 个 development transactions。信息更真实，但单人切换成本更高，不作为默认。

## 不论选什么都固定

- 不接触正式 test；
- perception/identity/dependency 在 updater 主比较中固定；
- oracle evaluator 必须 100%；
- 失败输入保留；
- run/fixture 保存 D-024 与 HC-018 对应的最终 decision ID；
- 完成第一批数据不等于模型已验证。
