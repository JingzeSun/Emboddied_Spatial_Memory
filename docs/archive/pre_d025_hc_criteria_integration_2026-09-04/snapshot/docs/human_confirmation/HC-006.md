# HC-006 — 多个目标候选时何时必须澄清

> 本文件已经内嵌指标解释与数字算例；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。

## 要决定什么

两个或更多对象都符合用户表达时，系统应直接选择、返回排序、同时处理，还是先询问。该决定只能影响 ActiveContext 和 action，不得改写世界事实。

## 固定不变量

- top-1 未选中的实例仍保留；
- prompt/路线只改变候选排序；
- identity ambiguity 与 referent ambiguity 分开；
- query 前后 ConfirmedGraph 必须 zero-delta。

## 必须由研究者选择

1. “有代价或风险的不同动作”如何量化；
2. 哪种任务代价必须澄清，哪种可以直接尝试；
3. 返回列表是否等同于澄清；
4. 最多展示多少候选；
5. 用户无法响应时的 fallback；
6. 分数差距是否参与询问门，阈值怎样 validation 冻结；
7. identity ambiguity 是否必须先于 referent clarification 处理。

## 推荐判题与指标

### 指标是什么意思

- **Recall@K**：正确目标是否还保留在前 K 个候选中。它检查系统有没有过早丢弃正确实例。
- **Top-1 accuracy**：排第一的候选是否真是用户想找的对象。
- **Clarification precision**：系统决定追问的场景中，确实存在不可安全消除歧义的比例。
- **Clarification recall**：真正需要追问的场景中，系统实际追问的比例。
- **Unnecessary clarification rate**：本来可以直接回答却仍追问的比例。
- **Context contamination rate**：当前任务 prompt 或最近提及错误改写长期世界事实的比例。

### 数字怎么算

100 个查询中，60 个语义明确，40 个确实歧义。系统对 35 个歧义场景和 10 个明确场景发起追问：

- Clarification precision = 35 / (35 + 10) = **77.8%**。
- Clarification recall = 35 / 40 = **87.5%**。
- Unnecessary clarification rate = 10 / 60 = **16.7%**。

两个木箱候选得分分别是 0.52 和 0.48，分差为 0.04。如果规则冻结为“分差小于 0.10 必须追问”，该场景不能直接选 top-1，更不能从世界图删除另一个木箱。

100 个查询中正确木箱 92 次仍在 top-2，78 次排第一：

- Recall@2 = 92 / 100 = **92%**。
- Top-1 accuracy = 78 / 100 = **78%**。

### 你需要冻结的选择

1. K 取 2、3 还是其他值。
2. 用候选分差、概率、空间约束还是风险决定是否追问。
3. 最多允许追问几次，以及用户不回答时怎么办。
4. ActiveContext 保留多久、何时清空。
5. context contamination 是否必须为 0；找错一次和多问一次的相对代价。

- 推荐：只有歧义会导致不同且不可忽略的动作代价/风险时询问；
- oracle 硬门：query world-belief delta=0、所有可行实例保留、危险动作不越过 safety gate；
- 指标：referent recall@k、accuracy@1、clarification precision/recall、task cost、nonselected preservation；
- 每个场景保存 acceptable action/query set，不强迫唯一话术。
