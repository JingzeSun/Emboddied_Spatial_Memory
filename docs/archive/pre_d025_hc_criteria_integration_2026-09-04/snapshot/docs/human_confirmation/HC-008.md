# HC-008 — 候选 hypothesis 何时提升为 confirmed fact

> 本文件已经内嵌指标解释与数字算例；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。

## 要决定什么

定义 PROPOSE、RETAIN、PROMOTE、REJECT 的证据门，尤其区分“多帧重复同一证据”和“多个独立证据”。

## 固定不变量

- 模型 prior 本身不能完成 PROMOTE；
- 只确认被观测覆盖的结构，不外推无限走廊；
- 证据冲突时保留/拒绝候选，不静默写事实；
- promotion 必须保存来源与确认历史。

## 需要定义的“独立证据”

- 不同 pose/viewpoint；
- 不同时间且场景有重新可见；
- 不同传感器且不存在共同 pose 错误；
- 主动动作产生的预期判别观测；
- topology/geometry/semantic 中不同证据族。

## 必须由研究者选择

1. 不同结构类型是否使用不同 promotion 门；
2. 单一强 3D 证据能否直接确认局部事实；
3. 最少独立证据族和时间/视角跨度；
4. 层级候选能否部分晋升；
5. 候选 aging/expiry 规则；
6. 被拒绝候选重新开启的条件；
7. 人工提示、VLM、simulator oracle 各自可否作为运行时确认依据。

## 推荐判题与指标

### 指标是什么意思

- **Promotion precision**：升级成 confirmed fact 的候选中，后来证明正确的比例。它回答“升级有多可信”。
- **Promotion recall**：真实存在的新结构中，最终被升级为事实的比例。它回答“系统是否过度保守”。
- **Premature promotion rate**：证据还没达到人工规则就提前升级的比例，即使后来碰巧猜对也属于流程错误。
- **Evidence-to-promotion**：从首次发现到升级用了多少条独立证据、多少帧或多少个动作。
- **Expiry correctness**：应过期候选被正确降级或删除的比例。
- **Calibration**：系统给出的 0.8 可信度是否真的对应约 80% 的正确率。

### 数字怎么算

系统升级 50 个候选，其中 45 个最终为真；人工标注共有 60 个真实新结构：

- Promotion precision = 45 / 50 = **90%**。
- Promotion recall = 45 / 60 = **75%**。

另有 10 个候选在只有一帧弱证据时就升级，而规则要求两条独立证据：

- Premature promotion 次数是 **10**，不是只统计其中后来被证明错误的候选。

20 个置信度约 0.8 的候选中，最终只有 10 个为真，实际正确率为 10 / 20 = **50%**。这说明 0.8 没有校准好，不能直接解释成“八成会是真的”。

### 你需要冻结的选择

1. 什么叫两条独立证据：不同帧、不同视角、不同传感器还是不同动作。
2. 升级阈值、降级阈值和候选最长寿命。
3. precision 与 recall 哪个优先，是否分别设置最低线。
4. 一次强证据能否替代多次弱证据。
5. 人工确认能否直接升级，以及相关连续帧如何避免重复计证据。

- 推荐：pose/geometry 一致 + 区域真实可见 + 多帧或独立证据；阈值 validation 冻结；
- oracle 硬门：S01/S03/S05/S06/S09/S10/S12/S19 不得完整 PROMOTE；
- 指标：promotion precision/recall、rejection accuracy、confirmation delay、ECE/Brier、false expansion、recovery；
- hard state accuracy 与 soft calibration 分开报告。
