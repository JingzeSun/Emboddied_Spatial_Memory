# HC-005 — 多个最小修订都正确时怎样判分

> 本文件已经内嵌指标解释与数字算例；[统一术语索引](METRIC_GUIDE.md)仅供查词。示例值不等于正式阈值。

> 状态与最终回答只见 [DECISIONS.md](../DECISIONS.md)。

## 要决定什么

同一 posterior 可能由不同但等价的操作序列得到。需要定义“结果等价”“操作等价”和“最小”分别是什么意思，避免 evaluator 伪造唯一答案。

## 固定不变量

- target invariants、必要传播、control preservation 和版本合法性优先于操作字符串 exact match；
- derived 关系不应强迫显式 edit；
- 操作顺序不同但最终版本语义相同可以等价；
- 多改无关事实不能因最终任务成功而被接受。

## “最小”的候选定义

| 定义 | 优点 | 风险 |
|---|---|---|
| 最少操作数 | 简单 | 一个粗大操作可能隐藏多改 |
| 最少编辑节点/边 | 对局部性直观 | 不同 schema 表示不公平 |
| 最小语义变化 | 最符合目标 | 需要 predicate/operator 合同 |
| 最低加权成本 | 可结合存储/延迟 | 权重需要冻结 |
| Pareto set | 不强迫单一权重 | evaluator 更复杂 |

## 必须由研究者选择

1. 结果、操作序列和 scope 哪一层允许等价；
2. 最小性使用操作数、编辑事实数、语义成本还是 Pareto set；
3. derived edge 是否排除在 edit size 外；
4. 是否接受多个 stop boundary；
5. 几何/置信度容差怎样从 validation 冻结；
6. full-graph 得到正确结果时算“正确但低效”还是 hard failure；
7. action acceptable set 的效用容差。

## 推荐判题与指标

### 指标是什么意思

- **Semantic validity**：修订后的世界是否同时符合新证据和所有不变量。它应先于“改得少不少”检查。
- **Weighted edit cost**：不同类型修改的次数乘以各自成本后求和，用来表达“删除身份比改一条位置关系严重”。
- **Excess edit cost**：系统方案成本减去可接受方案中的最低成本。
- **Equivalent-set accuracy**：系统答案是否落入人工预先标注的多个可接受答案之一。
- **Determinism**：同一输入重复运行时，是否得到相同修订或同一个等价类。

### 数字怎么算

示例设定：修改一条关系成本 1，新增节点成本 3，删除一个已有 identity 成本 10。

- 方案 A：修改 3 条关系，cost = 3 × 1 = **3**。
- 方案 B：删除旧节点再新建节点，cost = 10 + 3 = **13**。
- 如果 A、B 都满足证据，B 的 excess edit cost = 13 - 3 = **10**。

但如果 A 违反“两个真实实例不能共用一个 identity”，A 的成本即使更低也必须先判 semantic invalid，不能因为 3 小于 13 就胜出。

100 个场景中有 20 个允许两种答案。系统 18 次落入 acceptable set：

- Equivalent-set accuracy = 18 / 20 = **90%**。

### 你需要冻结的选择

1. 节点、边、状态、identity、删除和新增各自的 edit cost。
2. 哪些不变量是硬门，永远不能用更小 cost 抵消。
3. acceptable set 是按最终图、操作序列还是语义等价类定义。
4. 同成本方案如何打破平局。
5. 是否要求同一输入重复运行 100% 落在同一等价类。

- 推荐先判硬不变量，再在所有合法解中比较 semantic edit cost；
- evaluator 接受 `allowed_equivalence_class`，不 exact match 单一 JSON；
- 指标分开：posterior validity、operator correctness、scope size、collateral revision、latency/storage；
- oracle 硬门：任何等价答案都必须版本合法、无 control mutation、无 unknown fabrication。
