# HC-017：结构化基线准入与控制变量公平性

## 为什么必须由人确认

外部论文常同时更换 perception、tracking、association、map representation 和 updater。如果直接比较
端到端总分，无法判断优势来自“后验修正”还是更好的上游。另一方面，把只有最终 snapshot 的方法
强行要求输出 operation/provenance，再把缺失项记 0，也是不公平的。

这个选择决定哪些方法进入主因果比较、哪些只进共同指标赛道，以及论文能够声称什么。

## 固定不变量

- 本项目核心自变量是 posterior updater；主实验固定 `B_t/O_t/I_t/V_t/Q_t/D/base_version`。
- 未实现、无法复现或无法接相同输入的方法不得伪造数值。
- N/A 不得记为 0；共同指标与本项目专属合同指标分开报告。
- 结构表示是否有价值，必须通过表示消融验证，不能从 updater 对比中顺便推出。

## SA1–SA7 各是什么意思

| ID | 含义 | 具体数字例子 |
|---|---|---|
| SA1 Persistent entities | 同一实体能否跨时刻保持 identity | 20 个跨帧对象中 18 个保持稳定 ID，identity coverage=90%；但“能做 90%”不等于准入通过，剩余 2 个必须有 unknown/quarantine 表达 |
| SA2 Explicit facts | 内部状态能否确定性导出实体属性或谓词事实 | 100 个状态槽可导出 96 个，coverage=96%；丢失 4 个事实要进入 adapter loss |
| SA3 Typed relations | 边是否有明确 predicate，而非无类型相似度 | 8 类 gold 关系只能区分 6 类，则 relation-type coverage=75% |
| SA4 Prior-conditioned update | 新状态是否真实读取旧 belief | 把同一观测分别接两个不同 prior，输出应按冲突不同而变；10 对反事实中 0 对变化说明可能没有用 prior |
| SA5 Selective mutation | 能否恢复 preserve/retract/add/replace 等事实级变化 | 40 个 gold operations 中可无歧义恢复 34 个，operation observability=85%，不能参加操作指标主表 |
| SA6 Canonical export | adapter 是否无损、确定、可复测 | smoke 中 120 个事实两次导出一致且全对为 100%；117/120=97.5% 不过硬门 |
| SA7 Fixed upstream | 是否可与其他 updater 接收同一份输入 | 若方法必须使用自己的 detector，SA7 失败，只能进入 external end-to-end track |

SA1–SA6 同时通过才叫 `native_structured_revision`；能稳定投影最终图但缺少 SA5 的叫
`projected_structured_snapshot`；其余叫 `unstructured_or_per_frame_control`。

## 典型判定场景

### S01：论文自称 scene graph，但每帧重建

- 输入：t1/t2 都输出 object-relation graph，没有持久 ID，也不读旧图。
- 判定：SA2/SA3 可通过，SA1/SA4/SA5 失败。
- 允许：snapshot track 比最终 node/edge F1。
- 禁止：称它为事实级 selective revision 基线并比较 operation precision。

### S02：外部动态图可读旧图，但只能使用自有检测器

- 输入：方法能维护 ID/关系和状态，却无法接受 fixed canonical observation。
- 判定：可能是 native structured system，但 SA7 失败。
- 允许：单独报 end-to-end 结果，明确上游不同。
- 禁止：用其结果证明某个 updater 优于另一个 updater。

### S03：adapter 丢关系

- 输入：canonical fixture 有 120 个事实，其中 10 个 `supports`；adapter 输出 117 个，漏 3 个
  `supports`。
- 结果：整体 97.5%，传播需要的关系只保留 7/10=70%。
- 判定：适配器硬门失败，先修 adapter，不运行正式比较。

### S04：最终图一样，历史不同

- 方法 A 正确执行 2 个操作；方法 B 先误删 5 个无关事实，再全部补回。
- 二者最终 fact F1 都为 100%，但 B 的 collateral touches=5、version-chain 污染存在。
- snapshot 方法只能拿到共同的 100% F1；不能推断它在历史指标上等价。

## 可选方案

### 选项 A：分层准入 + canonical 主实验（建议）

- 主表只比较能读取完全相同 canonical input 的 updater。
- 外部方法按三层标签进入 full-contract、snapshot-common 或 end-to-end track。
- smoke adapter fidelity 必须 100%；损失字段显式列出。
- 另做结构消融：flat facts、untyped graph、no dependency、no control、no provenance/version。

优点：最能支持因果归因，也不惩罚原论文没有设计的输出。代价：需要自己实现若干简单确定性基线，
外部系统可能只能比较一部分指标。

### 选项 B：按作者自称“structured”纳入

省事，但 taxonomy 不可复核，不同方法实际结构和上游不一致，结论容易被审稿人质疑。

### 选项 C：只做端到端系统总分

最接近原论文设置，但无法隔离 posterior revision 贡献；只适合外部效度补充，不适合作核心实验。

## 还需一并确认的四个细项

1. 是否接受 smoke adapter fidelity 必须 100%，而不是 95%/99%？推荐 100%，因为这里只有少量人工 fixture。
2. snapshot 方法缺少 operation/version 输出时是否记 N/A？推荐是，不记 0。
3. 不同数据集是否禁止合并成一个 headline 平均分？推荐是，分别报告 AI2-THOR、3RScan、Dyn-THOR。
4. 是否将 `incident_edge_recompute` 作为必须击败的强局部基线？推荐是；只击败 overwrite 太弱。
