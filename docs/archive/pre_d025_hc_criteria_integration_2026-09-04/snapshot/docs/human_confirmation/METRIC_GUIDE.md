# HC 指标白话说明与数字算例

> 用途：帮助人工确认 HC-001～HC-018 中的评价标准。本文中的数字全部是“怎么算”的示例，不是已经接受的阈值。最终采用的指标、阈值、失败边界和例外情况，仍须写回 DECISIONS.md。

## 0. 先弄清楚你究竟要定什么

每个 HC 通常不是让你发明一个分数，而是让你确定下面六件事：

1. **什么算正确**：允许唯一答案，还是允许多个同样合理的答案。
2. **什么绝对不能发生**：例如把定位漂移误写成新走廊、把暂时看不见误判成物体消失。
3. **用哪个分母计算**：按帧、按对象、按事件、按轨迹还是按完整任务计算。
4. **达到多少才算通过**：例如 100 个事件至少正确 90 个。
5. **不同错误是否同样严重**：漏掉一次更新和错误删除整段地图，通常不能等价计分。
6. **不确定时能否回答 unknown 或主动再观察**：如果允许，就要规定何时可以用，不能靠无限拒答获得高准确率。

### 0.1 三类评价标准

- **硬门槛**：一旦发生就判本轮失败，不能被其他高分抵消。例如穿墙规划、修改测试集阈值、无证据删除整段世界图。
- **核心指标**：直接回答这个 HC 是否解决。例如关系传播召回率、错误世界修改率。
- **诊断指标**：帮助定位失败原因，但不单独支撑论文结论。例如运行时间、候选数量、平均传播半径。

### 0.2 最常见的计算词

假设系统说“有 10 个事件满足条件”，其中 8 个说对了；人工标注一共存在 12 个真正满足条件的事件：

- Precision（精确率）= 说对的数量 / 系统说有的数量 = 8 / 10 = 80%。它回答“系统一旦下结论，有多可信”。
- Recall（召回率）= 说对的数量 / 实际应该找到的数量 = 8 / 12 = 66.7%。它回答“该处理的事情漏掉了多少”。
- F1 = 2 × Precision × Recall / (Precision + Recall) = 72.7%。它用于同时关心误报和漏报的情况。
- Accuracy（准确率）= 全部判对数量 / 全部样本数量。类别极不均衡时可能骗人。例如 100 帧中 95 帧都没变化，系统永远回答“没变化”也有 95% accuracy。
- Rate（发生率）= 某类事件数 / 约定分母。必须写清楚“每帧、每对象还是每次轨迹”。
- Latency（延迟）= 从证据第一次足够到系统形成正确结论之间隔了多少帧、多少秒或多少动作。

## HC-001：物体身份是否连续

### 你需要决定

- 物体短暂消失后再次出现，什么时候仍算同一个实例。
- 错把两个物体合成一个，与把一个物体拆成两个，哪个更严重。
- 最多允许遮挡多久、位姿偏差多大、外观变化多大。

### 建议看的指标

- **ID switch rate**：同一真实物体被错误换 ID 的次数 / 该物体被成功跟踪的相邻时刻数。
- **False merge rate**：两个真实物体被合成一个 ID 的事件数 / 有合并风险的事件数。
- **False split rate**：一个真实物体被拆成多个 ID 的事件数 / 有重识别需求的事件数。
- **Identity recovery**：遮挡结束后恢复原 ID 的物体数 / 遮挡后重新出现的物体数。

### 数字例子

20 个物体各经历一次遮挡，其中 17 个恢复原 ID，2 个获得新 ID，1 个被并入旁边同类物体：

- Identity recovery = 17 / 20 = 85%。
- False split = 2 / 20 = 10%。
- False merge = 1 / 20 = 5%。

如果错误合并会导致系统删除或搬动错误物体，可以把 false merge 设为硬门槛，而不是与 false split 取平均。

### 你最后要填

分母按对象还是按重现事件；允许遮挡长度；允许位姿误差；false merge 是否必须为 0；同类物体交换位置时允许保留多假设多久。

## HC-002：哪些关系存储，哪些关系临时推导

### 你需要决定

- 哪些关系是世界事实，必须持久保存。
- 哪些关系可以由位置或其他关系算出来，不应重复存储。
- 基础关系变化后，旧的派生关系多久内必须失效。

### 建议看的指标

- **Relation precision / recall**：系统输出关系中正确的比例，以及真实关系中被找到的比例。
- **Derived consistency**：派生关系与当前基础事实一致的数量 / 被检查的派生关系数量。
- **Stale relation rate**：基础事实已变，但旧派生关系仍被返回的数量 / 应该失效的关系数量。
- **Storage ratio**：实际持久存储的关系数 / 如果全部关系都存储时的关系数。

### 数字例子

场景中人工标注 40 条有效关系。系统输出 38 条，其中 34 条正确：

- Precision = 34 / 38 = 89.5%。
- Recall = 34 / 40 = 85%。

位置改变后有 10 条旧派生关系应失效，其中 2 条仍能被查询到：

- Stale relation rate = 2 / 10 = 20%。

如果完整存储需要 100 条关系，而方法只存 35 条基础关系，其余实时推导：

- Storage ratio = 35 / 100 = 35%。
- 但只有在派生一致性不下降时，这个压缩才有意义。

### 你最后要填

逐个关系谓词确定“存储/推导”；关系冲突时谁优先；stale relation 是否为硬错误；是否允许近似几何关系；存储节约和正确率哪个优先。

## HC-003：变化应该传播到哪里，又在哪里停止

### 你需要决定

- 一个节点变化后，哪些依赖关系必须跟着更新。
- 哪些无关节点绝不能被修改。
- 存在多个合法最小影响范围时，哪些都可以接受。

### 建议看的指标

- **Propagation recall**：实际被正确更新的必要节点或边 / oracle 标注的必要更新总数。
- **Scope precision**：正确更新的节点或边 / 系统实际修改的节点或边总数。
- **Collateral revision rate**：不该改却被改的元素数 / 原本不该改的元素数。
- **Stop violation**：传播越过明确停止边界的次数。
- **Edit size**：一次事件改了多少节点和边，用于比较局部修订与全图重算，不代表越小越好。

### 数字例子

椅子从房间 A 搬到 B。人工判定必须更新 5 项：椅子位置、所在房间、A 的包含关系、B 的包含关系和一条邻近关系。系统改了 7 项，其中正确覆盖 4 项，另外错误改了 3 项：

- Propagation recall = 4 / 5 = 80%。
- Scope precision = 4 / 7 = 57.1%。
- 漏了 1 个必要修改，又污染了 3 个无关事实。

如果“门的身份”被规定为停止边界，但系统越过边界把门类型也改了，则本场景直接记 1 次 stop violation。

### 你最后要填

每类 operator 的允许依赖边；哪些边是停止边界；漏传播和多传播的代价；是否要求 stop violation 为 0；多个最小作用域如何判为等价正确。

## HC-004：什么时候可以说“它真的不在了”

### 你需要决定

- 看不见、被遮挡、传感器失败和真实移除如何区分。
- 需要几次观察、哪些视角或多少覆盖率才能确认 absence。
- 证据不足时输出 unknown，还是继续保留旧事实。

### 建议看的指标

- **Absence precision**：系统宣称“不在了”的事件中，真实移除的比例。
- **Absence recall**：真实移除事件中，被系统确认的比例。
- **False absence rate**：仍存在却被判消失的事件数 / 仍存在但不可见的事件数。
- **Confirmation latency**：真实移除发生后，多少帧或多少次主动观察才确认。
- **Abstention rate**：系统输出 unknown 的事件数 / 全部判定事件数。

### 数字例子

有 30 次真实移除和 70 次“仍在但被遮挡”。系统宣布 25 次“不在了”，其中 22 次是真实移除，3 次其实只是遮挡：

- Absence precision = 22 / 25 = 88%。
- Absence recall = 22 / 30 = 73.3%。
- False absence rate = 3 / 70 = 4.3%。

如果另外 40 次都回答 unknown，precision 可能很好看，但系统几乎不工作，所以必须同时报告 abstention rate。

### 你最后要填

absence 所需最少独立证据数；可靠视角定义；false absence 是否绝对禁止；最大确认延迟；unknown 的允许比例。

## HC-005：多个修订方案都说得通，怎样判哪个更好

### 你需要决定

- 评价器是否接受多个语义等价答案。
- 节点修改、关系修改、删除事实和改变身份分别有多大代价。
- “修改最少”是否必须服从“事实正确”和“安全”。

### 建议看的指标

- **Semantic validity**：修订后的图是否满足观察证据和不变量，通常应作为硬门槛。
- **Weighted edit cost**：各类修改次数乘以人工设定代价后的总和。
- **Excess edit cost**：系统代价 - 可接受方案中的最小代价。
- **Equivalent-set accuracy**：系统结果落入人工给出的可接受答案集合的次数 / 场景数。
- **Determinism**：相同输入重复运行得到相同结果的比例。

### 数字例子

设“改一条关系”成本 1，“新增节点”成本 3，“删除身份”成本 10。

- 方案 A：改 3 条关系，成本 = 3 × 1 = 3。
- 方案 B：删旧节点再建新节点，成本 = 10 + 3 = 13。

若两者都解释观察，则 A 更小，B 的 excess edit cost = 13 - 3 = 10。但如果 A 违反“两个实例不能共用一个 ID”，即使成本更低也必须判失败。

### 你最后要填

各 operator 的成本；哪些语义约束先于最小化；可接受答案集合怎样标注；同成本如何打破平局；是否要求重复运行 100% 一致。

## HC-006：什么时候直接回答，什么时候追问用户

### 你需要决定

- 两个同类候选差多少时可以直接选，差多少时必须澄清。
- 用户最近提到的对象只影响本次排序，还是可以修改长期世界事实。
- 系统允许澄清多少次。

### 建议看的指标

- **Candidate recall@K**：正确对象是否出现在前 K 个候选中。
- **Top-1 accuracy**：排第一的对象是否是用户真正指的对象。
- **Clarification precision**：系统选择追问的场景中，确实需要追问的比例。
- **Unnecessary clarification rate**：本可直接回答却追问的次数 / 可直接回答的场景数。
- **Context contamination rate**：任务语境错误改写长期世界事实的次数 / 任务查询次数。
- **Task success after clarification**：追问后最终找对对象的比例。

### 数字例子

100 个查询中，60 个语义明确，40 个确实歧义。系统对 35 个歧义场景和 10 个明确场景发起追问：

- Clarification precision = 35 / 45 = 77.8%。
- 歧义场景召回 = 35 / 40 = 87.5%。
- Unnecessary clarification rate = 10 / 60 = 16.7%。

两个木箱的候选分数为 0.52 和 0.48，差值只有 0.04；如果你规定差值小于 0.10 必须追问，这时就不能直接删除第二个候选。

### 你最后要填

K 取多少；候选分差阈值；最多追问次数；任务语境的有效期；context contamination 是否必须为 0；回答错误和多问一次哪个代价更大。

## HC-007：计划去过，不等于真的去过

### 你需要决定

- planned、executing、executed 和 failed 的切换条件。
- 使用命令、里程计、视觉还是到达确认作为执行证据。
- 位姿漂移多大时停止扩图并转入定位修复。

### 建议看的指标

- **Execution-state accuracy**：计划状态被正确分类的比例。
- **False execution rate**：只计划或执行失败，却被记成已执行的事件数 / 未成功执行事件数。
- **Pose consistency**：观测在当前位姿假设下能否与地图对齐。
- **ATE / position error**：估计位置与参考位置的距离误差；可报告均值、中位数和 95% 分位。
- **Phantom expansion rate**：因为把计划当执行而新增的虚假节点数 / 全部新增节点数。

### 数字例子

机器人收到 20 次左转命令，其中 15 次真正完成，3 次被障碍阻止，2 次尚未执行。系统却记录了 18 次“已完成”：

- 3 次失败中有 2 次被误记，2 次未执行中有 1 次被误记。
- False execution rate = 3 / 5 = 60%。

10 个定位点误差分别统计后，中位数 0.18 m、95% 分位 0.72 m。若转角宽度只有 0.6 m，0.72 m 可能足以制造假岔路，因此阈值必须和场景尺度绑定。

### 你最后要填

状态转换所需证据；位置和角度容差；漂移触发条件；未执行命令是否可以生成候选但不能生成事实；phantom expansion 是否为硬错误。

## HC-008：候选什么时候能升级成世界事实

### 你需要决定

- 一次强证据与多次弱证据怎样比较。
- 同一传感器连续多帧是否算独立证据。
- 候选多久未获支持后降级或删除。

### 建议看的指标

- **Promotion precision**：升级为事实的候选中，后来被证明正确的比例。
- **Promotion recall**：真实新结构中，最终被升级为事实的比例。
- **Premature promotion rate**：证据尚未达到人工标准却被升级的次数 / 全部升级次数。
- **Evidence-to-promotion**：从首次发现到升级用了几条独立证据或几个动作。
- **Candidate expiry correctness**：过期处理正确的候选数 / 应过期候选数。
- **Calibration**：系统说 80% 可信的一组候选，是否大约有 80% 最终为真。

### 数字例子

系统升级 50 个候选，其中 45 个为真；人工标注共有 60 个真实新结构：

- Promotion precision = 45 / 50 = 90%。
- Promotion recall = 45 / 60 = 75%。

另有 10 个候选在只有一帧模糊证据时就升级，其中 4 个后来为假：

- 若规则要求两条独立证据，这 10 个都属于 premature promotion，而不仅是其中 4 个假候选。

校准例子：20 个置信度约 0.8 的候选最后只有 10 个为真，实际正确率 50%，说明 0.8 不能直接当作可靠概率。

### 你最后要填

独立证据定义；升级和降级阈值；候选最长寿命；precision 与 recall 哪个优先；是否允许人工确认直接升级；如何处理证据相关性。

## HC-009：新节点能挂在哪里，类型和层级是否合理

### 你需要决定

- 哪些节点类型可以连接哪些关系和父节点。
- 新区域、房间、走廊、物体的层级约束。
- 无法确定父节点时保留 orphan、挂 unknown，还是拒绝新增。

### 建议看的指标

- **Type validity**：新增节点和边满足类型约束的数量 / 全部新增节点和边。
- **Attachment accuracy**：新节点挂到正确父节点或锚点的数量 / 需要连接的新节点数。
- **Hierarchy consistency**：没有循环包含、非法跨层连接等问题的图 / 被检查的图。
- **Orphan rate**：没有合法连接点的新节点数 / 全部新增节点数。
- **Duplicate-node rate**：本应连接旧节点却错误新建的节点数 / 全部新增节点数。

### 数字例子

新增 30 个节点，其中 26 个类型合法；24 个挂对父节点，3 个挂错，3 个暂存 unknown；另有 2 个其实是旧节点的重复副本：

- Type validity = 26 / 30 = 86.7%。
- Attachment accuracy 若 unknown 也算未完成，则 = 24 / 30 = 80%。
- Orphan/unknown rate = 3 / 30 = 10%。
- Duplicate-node rate = 2 / 30 = 6.7%。

unknown 是否暂不计错必须提前规定，否则不同方法无法公平比较。

### 你最后要填

类型兼容表；允许的父子层级；unknown/orphan 的有效期；重复节点的判定半径；非法类型是否硬失败；多父节点是否允许。

## HC-010：这是新走廊、旧地点回环，还是定位漂移

### 你需要决定

- 三类解释各需要什么证据。
- 系统可以保留多假设多久。
- 哪种混淆最危险，是否要单独设硬门槛。

### 建议看的指标

- **三分类 confusion matrix**：逐项统计 new、loop、drift 被判成了什么。
- **Per-class precision / recall**：分别看三类，不能只看总准确率。
- **Macro-F1**：三个类别的 F1 直接平均，避免数量最多的类别掩盖少数类失败。
- **False map expansion**：回环或漂移被误判为新区域而产生的虚假扩图次数。
- **False loop closure**：真实新区域被错误合并回旧地点的次数。
- **Decision latency**：保留假设多久后作出决定。

### 数字例子

测试有 new 40 个、loop 30 个、drift 30 个。系统判对 new 32、loop 24、drift 15，总准确率是 71%。但 drift recall = 15 / 30 = 50%，说明系统对漂移很差。

若 30 个 loop 中有 5 个被判成 new，30 个 drift 中有 10 个被判成 new：

- False map expansion 事件 = 15。
- 如果这 15 次各新增 4 个虚假节点，则还可以报告 60 个虚假节点，而不是只说 15 次错误。

### 你最后要填

三类标注规则；位姿与外观阈值；是否采用 macro-F1；false loop closure 和 false expansion 哪个代价更高；多假设最长保留帧数。

## HC-011：只是视野揭示、传感器异常，还是世界真的变了

### 你需要决定

- 新看到旧场景的隐藏部分是否只补可见性和几何。
- 什么证据能触发真实世界修订。
- 深度、视觉和位姿相互冲突时先信谁，何时进入 quarantine。

### 建议看的指标

- **Event classification macro-F1**：分别评价 reveal、sensor inconsistency、world change。
- **False world-edit rate**：揭示或传感器异常被错误写成世界变化的事件数 / 非真实变化事件数。
- **Missed-change rate**：真实变化却未修改世界的事件数 / 真实变化事件数。
- **Reveal completion**：新视角应补充的结构中成功补充的比例。
- **Quarantine precision**：送入待确认区的事件中确实存在证据冲突的比例。
- **Recovery latency**：传感器恢复后，多少帧解除 quarantine 并回到正确状态。

### 数字例子

数据中有 40 次视野揭示、20 次传感器异常、20 次真实变化。系统把 5 次揭示和 4 次异常误写成世界变化：

- False world-edit rate = 9 / 60 = 15%。

系统发现了 16 次真实变化：

- Missed-change rate = 4 / 20 = 20%。

如果“把遮挡误判成椅子被永久搬走”被认为不可接受，可以要求该子类 false world edit 为 0，而不是只看总体 15%。

### 你最后要填

三类事件的证据标准；哪些传感器冲突进入 quarantine；真实修订需要几次确认；false world edit 是否硬失败；恢复等待时间。

## HC-012：不确定时，机器人该去哪里再看一眼

### 你需要决定

- 任务收益、信息价值、风险和行动成本怎样比较。
- 安全限制是硬约束还是可以用高收益抵消。
- 选择最优动作，还是选择足够好且更安全的动作。

### 建议看的指标

- **Task success gain**：主动观察后任务成功率 - 不主动观察时任务成功率。
- **Uncertainty reduction**：观察前不确定性 - 观察后不确定性；必须说明用熵、候选数还是其他量。
- **Action cost**：距离、时间、能耗或动作次数。
- **Risk / safety violation**：碰撞、进入禁区、失去定位等事件。
- **Utility**：将收益、信息、风险和成本归一化后加权。
- **Regret**：oracle 最佳安全动作的收益 - 系统所选动作收益。

### 数字例子

先把各量缩放到 0～1，示例公式：

Utility = 0.5 × 任务收益 + 0.3 × 信息价值 - 0.1 × 成本 - 0.1 × 风险。

动作 A：任务收益 0.8、信息 0.5、成本 0.4、风险 0.1：

- Utility(A) = 0.5×0.8 + 0.3×0.5 - 0.1×0.4 - 0.1×0.1 = 0.50。

动作 B：任务收益 0.6、信息 0.8、成本 0.2、风险 0：

- Utility(B) = 0.30 + 0.24 - 0.02 = 0.52，因此示例权重下选 B。

但如果 A 有 5% 碰撞概率，而你把“碰撞概率必须低于 1%”定为硬约束，A 应先淘汰，不能靠其他收益抵消。权重 0.5/0.3/0.1/0.1 只是算例，不是推荐结论。

### 你最后要填

收益组成；各量如何归一化；权重；安全硬限制；最大动作预算；oracle 是什么；收益差多小时优先选更安全或更便宜动作。

## HC-013：七组实验怎样通过，怎样汇总

HC-013 不是再发明一个能力，而是冻结 E0～E6 各自的“及格线”和整个 pilot 的 Go / No-Go 规则。

按 D-022，E0 是判尺，E1/E2/E4 是 semantic/topology/time 前置，E3 是补证，E5 直接验证 affected/control/stop + versioned revision，E6 验证 Top-K/任务语境不能越权写世界。聚合时必须先看核心 revision，不能把七组当成七项创新后求平均。

### E0：先检查评价工具本身

- **要定什么**：schema、执行器和 evaluator 是否必须 100% 通过人工可计算样例。
- **例子**：准备 50 个极小 fixture，人工已经知道每个正确输出。如果 49 个通过，pass rate = 98%。对于基础评价工具，98% 通常不能解释为“模型不错”，而意味着评价基础设施仍有 bug。
- **建议性质**：E0 更适合硬门槛，不适合与后续实验平均。

### E1：能否根据新观察形成正确预测或新结构

- **要定什么**：正确扩展率、盲目延长率、预测被否定后是否撤回。
- **例子**：50 次走廊扩展中，系统正确提出 40 次候选，漏掉 5 次，另有 5 次在墙后盲目扩展。候选 recall = 40 / 45 = 88.9%；盲目扩展率 = 5 / 50 = 10%。
- **注意**：候选可以错，未经证据却直接写成事实是另一种更严重的错。

### E2：能否区分新区域、回环和漂移

- **要定什么**：是否用 macro-F1；三类各自最低 recall；哪种混淆属于硬失败。
- **例子**：三类 F1 分别为 0.90、0.80、0.40，则 Macro-F1 = (0.90 + 0.80 + 0.40) / 3 = 0.70。不能只报 0.70 后忽略 drift 几乎不可用。

### E3：主动观察是否真的值得

- **要定什么**：行动后是否减少关键不确定性、是否提高任务成功、成本和风险上限。
- **例子**：不主动观察时找对门的成功率为 60%，主动观察后为 78%，task success gain = 18 个百分点。平均多走 1.5 m、耗时 4 s，需要由你判断 18 个百分点是否值得这些成本。
- **失败例子**：虽然信息增多，但选择了高风险动作；或者只是移动了，相同候选仍无法区分。

### E4：候选升级是否过早或过慢

- **要定什么**：promotion precision、recall、证据条数和最长等待时间。
- **例子**：40 次升级中 36 次正确，precision = 90%；共有 50 个真实结构，召回 36 个，recall = 72%。高 precision 可能来自系统过度保守，必须同时看 recall 和延迟。

### E5：世界变化后是否只修改必要部分

- **要定什么**：必要传播召回率、无关修改率、停止边界和版本可追溯。
- **例子**：10 个事实必须更新，系统更新了其中 9 个，同时误改 2 个无关事实：propagation recall = 90%；scope precision = 9 / 11 = 81.8%。如果 2 个误改中包含人的身份类型，即使平均分不错，也可按不变量硬失败。

### E6：任务语境是否只影响当前选择

- **要定什么**：top-K 是否保留正确同类实例、最近语境带来的排序收益、世界事实污染率。
- **例子**：100 个“两木箱”查询中，正确箱子 92 次位于 top-2，Recall@2 = 92%；top-1 找对 78 次，Top-1 accuracy = 78%。如果系统为了提高 top-1 而从世界中删除另一个箱子，context contamination 应单独判失败。

### 七组实验如何汇总

不要把所有分数直接平均成一个漂亮总分。建议分三层：

1. **硬门槛层**：E0 正确；安全、不变量、测试集隔离、禁止污染等不得违反。
2. **模块层**：E1～E6 各自达到最低标准，避免一个强模块掩盖一个失效模块。
3. **端到端层**：完整轨迹是否真正完成任务，并保留正确、可追溯的世界状态。

### 数字例子

假设 E1～E6 得分分别为 92、88、91、85、94、90，平均 90 分；但 E2 中有 3 次把定位漂移写成新走廊，而该错误被设为 forbidden behavior。那么最终仍是 No-Go，不能用平均 90 分抵消。

另一种情况：所有硬门槛通过，E1～E6 最低分 82，预先规定每组至少 80，则模块层通过。此时再报告端到端任务成功率，例如 42 / 50 = 84%，而不是把 84% 和模块分数继续混成一个总分。

### 你最后要填

- E0 是否要求所有 fixture 100% 通过。
- E1～E6 每组的主指标、最低线和禁止行为。
- 接受唯一答案还是 acceptable set。
- 每类场景是否都要过线，还是只看总体。
- 至少多少场景、多少随机种子、多少条完整轨迹。
- 多次运行取均值、中位数还是最坏值。
- 哪些结果触发 Go、带条件继续或 No-Go。

## HC-014：当前帧的一块区域，究竟属于世界里的谁

### 你需要决定

- 什么线索共同证明“这是旧墙/旧地面/旧开口的再次观察”；
- 遮挡把同一表面切成两块时，何时允许临时 split，何时恢复 merge；
- 相似区域证据不足时，是建新节点、保留多个对应，还是 quarantine；
- 哪些对应结果可以更新长期 latent，哪些必须禁止写入。

### 建议看的指标

- **Association precision / recall**：系统给出的区域—世界节点对应有多少正确，以及真实对应找回多少；
- **Duplicate-node rate**：本应复用旧节点却新建副本的次数 / 新建节点次数；
- **False merge rate**：本应不同的世界表面被并到同一节点的次数 / merge 决策次数；
- **Split/merge recovery**：遮挡解除后，临时分块恢复到正确世界节点的比例；
- **Latent contamination**：无关或错绑区域特征写进目标节点的比例；
- **Control preservation**：本次观测无关的世界节点保持不变的比例；
- **Abstention quality**：系统说“不确定、先不写”时，是否确实是歧义样例。

### 数字例子

人工标注有 100 个真实 region-to-world 对应。系统提交 90 个对应，其中 81 个正确：

- Association precision = 81 / 90 = 90%；
- Association recall = 81 / 100 = 81%；
- 剩下 10 个未提交可视为 abstain，不能因为没写错就只报 precision。

机器人前进 20 步，本应只增加 4 个新表面，系统新增 10 个，其中 6 个其实是旧墙的重复副本：

- Duplicate-node rate = 6 / 10 = 60%；
- 也应报告每米新增节点数；例如移动 5 m 新增 10 个，即 2 nodes/m。

某次只允许更新 wall_1，另有 9 个 control nodes。系统错误改了 wall_2 和 floor_3：

- Control preservation = 7 / 9 = 77.8%；
- 若 wall_1 的新 latent 有 30% 权重来自错绑的 wall_2 特征，可报告 contamination = 30%。

### 你最后要填

区域来源组合；association 可接受集合；split/merge 规则；新节点门槛；abstain/quarantine 时限；长期 latent 写入门；重复节点、错误合并和污染哪些属于硬失败；各指标按帧、区域、表面、米还是轨迹统计。

更完整的 42 类场景和填写卡见 [HC-014 工作表](HC-014.md)。

## 14. 推荐的填写方式

对每一个要冻结的指标，复制下面这张卡片填写。没有写清分母和失败边界的指标，先不要进入正式实验。

| 项目 | 需要填写的内容 | 数字示例 |
|---|---|---|
| 指标名 | 衡量什么 | false world-edit rate |
| 统计单位 | 按帧、对象、事件、轨迹或任务 | 按事件 |
| 分子 | 哪些事件计数 | 错把揭示当变化的事件 |
| 分母 | 用什么总体相除 | 所有非真实变化事件 |
| 可接受答案 | 唯一答案或答案集合 | reveal / unknown 均可接受 |
| 硬门槛 | 发生一次是否直接失败 | 删除人物身份：是 |
| 通过线 | 多少算通过 | 示例：不高于 2% |
| 分组线 | 每个子场景是否单独过线 | 遮挡类必须为 0 |
| 不确定处理 | 是否允许 unknown，最多多少 | 示例：不超过 15% |
| 聚合方式 | 均值、macro、最坏组或全部通过 | 最坏组 |
| 阈值来源 | pilot、先验、安全要求或文献 | validation pilot |
| 冻结位置 | 最终写到哪里 | DECISIONS.md 对应 HC |

## 15. 防止指标“看起来很好但其实没解决问题”

- 同时报 precision 和 recall，避免只做保守拒答。
- 同时报总体与每类结果，避免多数类掩盖少数类。
- 把安全、不变量和世界污染设为独立硬门槛，不让平均分抵消。
- 明确 unknown 是否算错以及允许比例。
- 阈值只能用开发集或验证集确定；测试集只在冻结后使用。
- 先列 forbidden behavior，再决定加权总分。
- 记录失败案例原始输入、版本、随机种子和完整输出，不能只保留成功截图。
