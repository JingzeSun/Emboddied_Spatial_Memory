# VSMT-lean method specification (D-224)

> This file defines only the method of the current first paper: **the lean version of Versioned Structural Memory Transactions (VSMT-lean, versioned entity-lifecycle transactions)**. The method texts of the earlier CPMT, the spatial world model (D-062), the two-layer place memory (D-210), the unified four-type graph (D-213), and the eight-atom candidate enumeration with structure estimators (D-214–D-223) are archived with the branch `archive/pre-d224-unified-graph` and are not repeated here; read them from that branch or from the Git history when needed.
>
> Status: implemented and evaluated; the test split was read once in S3-05 (EXECUTE LOG-306). Sections keep their registration-time wording; later changes are given as dated rulings and corrections. Values marked "proposed", "planned" or "null" are registration-time placeholders; frozen values are in the S0 contracts (`configs/vsmt/lean_*.json`) and the corrections in this file.

## 1. Problem definition

VSMT-lean addresses the following problem: when a robot revisits a scene with a multi-view history, decide for each entity in its object-level memory whether it should be **kept, bound to new evidence, newly created, retracted or reactivated**. The input is the public observation O_t up to the current frame t (anonymous fragments produced by the frozen front end, public geometry, free space and visible volume, causal relative poses, action summaries) and the memory M_{t−1} previously predicted by the system itself; the output is a legal program Π_t for this frame composed of NOOP/BIND/BIRTH/RETRACT/REACTIVATE, the new memory version M_t = exec(M_{t−1}, Π_t), and the attribution of evidence. The method does not revise places or topology, does not learn SPLIT/RELINK, does not train the visual front end, and does not treat the executor, DINOv2 or the five operation names on their own as contributions.

Formally, the memory M_t is a set of entity records; the program Π_t is a set of per-fragment operations and per-entity existence decisions; exec is a deterministic executor that supports rollback and retains historical versions. exec only applies the rules and keeps the record of every change; Π_t is what is learned.

## 2. Positioning and core contributions

The paper's core contribution is the combination of the following three parts; none of them constitutes a claim on its own:

1. **Reversible lifecycle revision with hindsight supervision** (after S3-05, ruling 113 words this as a versioned, reversible lifecycle revision with learned costs; the gain over AssocOnly is not attributed to hindsight supervision itself). Private instance ground truth labels the sealed association/existence decisions, and a small cost function is trained on these labels; RETRACT only closes a version, and REACTIVATE can restore the same identity. It targets two opposing errors, stale entities that remain in memory and identities lost after an erroneous deletion, and produces reversible, versioned revisions from the same public features. The contribution is neither the renaming of labels as operations nor the retention of historical bytes.
2. **Candidate-before-teacher information boundary and three-way error decomposition.** Recall sets, feature matrices and assignment inputs are computed and sealed before any private file is opened; the teacher can only label existing rows and columns. Errors are split into recall miss (the correct entity is not in the recall set), teacher error (the label itself is wrong) and amortization error (the student disagrees with the label). This locates where a gain or a loss arises. The boundary is not established merely by the absence of a private argument from function signatures.
3. **Comparison with association, persistence and render-and-compare mechanisms under the same front end.** VSMT-lean, TAF, ELU-P, RAC and LOW read byte-identical frozen front-end caches, and the metrics are aligned with Dyn-THOR. This rules out front-end differences as the explanation of an advantage. It is not an official reproduction of these systems.

The paper may report whether, under a shared frozen public front end (simulator instance segmentation + RGB-D geometry + DINOv2, ruling 72), reversible lifecycle revision with hindsight supervision (after S3-05, ruling 113 words this as a versioned, reversible lifecycle revision with learned costs; the gain over AssocOnly is not attributed to hindsight supervision itself) reduces stale entities and erroneous deletions and preserves identity, together with the three-way decomposition. Under ruling 83-3 (planned at registration; delivered in S3-05, 2026-10-08, LOG-306), a second main table under SAM 2.1 segmentation is reported alongside the instance-segmentation main table, so that the paper may also report whether the conclusion holds under SAM 2.1 segmentation. It may not claim: place or topology revision, relation revision, learning of SPLIT/MERGE, metric SLAM, robustness to sensor noise, generalisation to real robots. The paper is planned at RA-L length; venue: see docs/DECISIONS.md (rulings 83-6 and 113-4).

**Pre-registered claim boundaries (ruling 102-1, 2026-10-02).** The research direction of the method is unchanged; what the paper may state for each S3 outcome is fixed before S3, and its wording can afterwards only be chosen within these boundaries: (1) if the primary test of the instance-segmentation main table (the first step of the fixed order in Section 11) passes numerically and VSMT-lean satisfies the registered feasibility condition of configuration selection (Section 9), the paper may state that "on ProcTHOR with the simulator instance-segmentation front end, the lifecycle operations of this training procedure (fixed training data, recipe and selection procedure, 5 seeds) leave fewer stale entities and re-attach identities better than the same recipe learning association only"; if the test passes numerically but the selection constraint cannot be satisfied, the numbers are reported as they are and this claim is not made; if the test does not pass, the primary hypothesis is not established, and the two metrics are reported only as differences with intervals; (2) the last two steps of the fixed order, under SAM 2.1, each support or fail to support the corresponding part of "it also holds under SAM 2.1"; (3) against the rule-based arms, trade-offs are always reported per metric (Missing residual rate, in-scope false-retract rate, node F1, identity continuity); the original gate (against the strongest control) is computed in S3 exactly as written and reported according to the actual result, and it has been recorded as not met on the development and confirmation sets; (4) the "protocol plus benchmark" framing (ruling 83-6) is not an automatic fallback: switching to it requires separate evidence of contribution and a separate ruling. ## 3. Memory representation

The **entity record** is the only node type of the memory. It holds the auditable information about one object: built from the fragment evidence attached by successive BIND/BIRTH/REACTIVATE operations, it exposes a queryable current state and a traceable version chain. It is not a place or a surface and contains no semantic class.

| Field | Meaning | Written by |
|---|---|---|
| `entity_id` | Anonymous stable ID, assigned at BIRTH; MERGE deduplication keeps the canonical one | executor |
| `state` | `active` / `dormant` / `retracted` | executor |
| `versions[]` | Each version contains `version_id`, `predecessor`, `opened_at`, `closed_at`, `closing_transaction` | executor |
| `descriptor_mean`, `descriptor_count`, `best_view_descriptor` | Running mean and count of the DINO descriptors, and the single-view descriptor of the observation with the most pixels | BIND/BIRTH/REACTIVATE |
| `centroid`, `aabb` | Centroid and axis-aligned bounding box in episode-relative coordinates, updated from the evidence at BIND, with the displacement recorded. The box is assembled only from the fragments belonging to the entity in the frame in which it was last seen: a new frame replaces it entirely, further fragments of the same frame are united with it, and nothing accumulates across frames (ruling 56 (cont.); cross-frame accumulation would merge depth noise into the box) | BIND/BIRTH/REACTIVATE |
| `observation_count`, `last_seen_t` | Number of observations and frame index of the last observation | BIND/BIRTH/REACTIVATE |
| `missed_opportunity_count` | Consecutive count of "should be visible but not matched"; reset by any match | shared dormancy rule |
| `evidence[]` | List of `(frame_digest, fragment_id)` | BIND/BIRTH/REACTIVATE |
| `supported_by` | Geometrically derived supporting-surface ID or null; all arms share the same deterministic rule. It is a geometrically derived attribute explicitly retained by D-224 ruling B, but it **does not enter the association features**: comparing by ID is informative only if surface IDs are stable across frames, and cross-frame-stable surface IDs amount to maintaining a persistent surface identity, which is exactly the capability removed from the first paper. The association head uses the purely geometric difference in supporting-surface height instead | shared geometric rule |
| `provenance` | Transaction ID and decision time that created/closed this version | executor |

**State machine.** `active` ⇄ `dormant` is governed by the deterministic dormancy rule shared by all arms (`AssocOnly` has no dormant state, Section 10): when the number of consecutive missed should-be-visible opportunities reaches `n_dormant` (null), the entity turns dormant; any match returns it to active. `active`/`dormant` → `retracted` is triggered only by RETRACT; `dormant`/`retracted` → `active` only by REACTIVATE. BIND can only target `active` entities. The NoVersion ablation replaces `retracted` with physical deletion. A dormant entity has missed `n_dormant` consecutive should-be-visible opportunities but there is no evidence that it is gone; a retracted entity has evidence that it is no longer at its original place; neither state deletes the record.

**Correction (2026-10-08, LOG-310; the sentence above is left unchanged)**: `n_dormant` is frozen at 3 consecutive misses (`DORMANCY_MISSED_OPPORTUNITY_LIMIT` in `src/vsmt/lean_memory.py`, S0-01 `shared_dormancy.dormancy_missed_opportunity_limit`; frozen by D-224-S1 ruling 67 on 2026-09-24, identical in the S3 freeze commit `dea8c20`); `AssocOnly` has no dormant state. The null above was the open value at S0; the code had long since fixed it at 3, and the paper states 3.

**Shared deduplication (MERGE).** Every `m_dedup` (frozen at 10) frames, a deterministic deduplication runs over active and dormant entities (ruling 76 (2)(a); retracted entities do not take part): a pair with cosine ≥ `θ_m` (frozen at 0.6 by ruling 77 (2)(a), originally 0.8), centroid distance ≤ `d_m` (0.5 m) and AABB IoU ≥ `i_m` (0.05) is merged into one record, closing the two old versions and keeping the canonical ID and all evidence. All arms execute the same rule byte-identically, and its parameters are selected only once, on the S1 development set. It removes duplicate entities produced by front-end over-segmentation; it is not a learned decision and does not contribute to any difference between methods. Handling of the folded entity (D-224-X ruling X6): its ID enters the canonical entity's `canonical_of`, all its evidence is merged into the canonical entity, and the transaction log keeps the record; its own version chain is no longer kept as a live record. This is called "archived into canonical_of" and does not count as physical deletion of historical versions — `physical_deletion_allowed=false` means that the lifecycle history of live entities is not deleted, whereas deduplication is the MERGE atom of the paper, not RETRACT. Each version record additionally carries `opened_by` (birth/bind/reactivate/retract/dormant/dedup/dedup_dormant), which states why it was opened and binds the state at that time. **Ruling 76 (2)(a) (2026-09-26)**: the merged centroid, box and surface points are taken from whichever of the two was seen later (if both were seen in the same frame, the boxes are united and the centroid is weighted by observation count); if either is active the result is active, and if both are dormant it stays dormant (`dedup_dormant`). Before this ruling only pairs of active entities were merged. AssocOnly never turns entities dormant, so its duplicates always remained mergeable, whereas the abandoned duplicates of the other arms escaped deduplication once they turned dormant; this introduced a difference unrelated to the lifecycle vocabulary into the only causal comparison of contribution 1 (VSMT-lean against AssocOnly). Eligibility now depends only on whether an entity is still in memory and is independent of each arm's existence decisions; it is not a retraction and does not change the three deduplication values (their review is a separate ruling).

**Entity token (D-224-G).** The entity token is a per-frame export of the memory for a downstream world model or planner: one row of ordered fields per non-retracted entity (`entity_id`, state one-hot, descriptor, centroid, size, observation count, age, number of versions, number of misses, and whether a supporting surface exists), plus a sparse per-frame residual that records which `entity_id` were changed by which atom in this frame. Entity tokens are not an experimental subject of the paper, which guarantees only that the schema and field order are frozen and exportable per frame; integration with a world model is future work.

**Executor invariants.** Every atom has preconditions; the program as a whole is executed on a clone of the same immutable M_{t−1}, and if any atom fails the whole frame is rolled back; historical versions are never physically deleted; within one frame a fragment lands on at most one entity; version numbers are monotone; provenance must be complete. The executor reuses the entity subset of `graph_ops.py` and `contracts.py` and does not introduce a second implementation. (Correction 2026-10-09: the executor is the self-contained module [`src/vsmt/lean_memory.py`](../src/vsmt/lean_memory.py), whose only project imports are `cpmt.hashing` (`canonical_json`, `clone_json`) and `vsmt.lean_geometry`; it reuses neither `graph_ops.py` nor `contracts.py`, see Section 13.)

## 4. The five atoms and the frame program

| Atom | Precondition | Effect | Decided by | Distinct from |
|---|---|---|---|---|
| `NOOP` | The target entity should be visible in this frame and is unmatched | Keeps the entity's state; `missed_opportunity_count` increases by one | existence head σ(r) < τ_r | ignoring the entity |
| `BIND` | The target entity is `active` | Appends evidence, updates descriptors/geometry, records the displacement | assignment f→active e | semantic-label matching |
| `BIRTH` | The fragment is not assigned to any entity | Creates an entity and its first version | assignment f→its own BIRTH column | treating every mask as a new entity |
| `RETRACT` | The target entity should be visible, is unmatched, and σ(r) ≥ τ_r | Closes the current version, sets the state to `retracted`, keeps the evidence | existence head | physical deletion |
| `REACTIVATE` | The target entity is `dormant` or `retracted` | Opens a new version, sets the state to `active`, updates the geometry and keeps the old ID | assignment f→dormant/retracted e | creating a new entity that resembles it |

`REPLACE` remains a composite program that, within the same frame and for the same location, first RETRACTs the old entity and then BIRTHs a new one; it is allowed only if both halves are legal on their own, and it does not count as a sixth atom. The **frame program** Π_t is the set of all atoms of the frame and is committed atomically at once; when the frame has neither fragments nor should-be-visible entities, the program is empty.

## 5. Shared frozen front end

The front end consists of the fragment source, the DINOv2 assets frozen by D-215 and deterministic geometry; all arms read byte-identical clones of the same cache. Apart from the shared re-identification (ReID) projection head (trained once per mask source, then frozen; see below), this project trains none of its front-end components. The fragment source and its caches are governed by the following rulings:

- **Ruling 72 (2026-09-25)**: the fragment source of the main table changes to simulator instance segmentation, and SAM 2.1 is demoted to a robustness appendix.
- **Ruling 83-3 (2026-09-29; planned at registration, delivered in S3-05, 2026-10-08, LOG-306)**: SAM 2.1 is promoted from the appendix to a second full main table; from S3 on, each of the two front ends gets its own cache, its own configuration selection and its own main table.
- **Ruling 84-3** (a correction): before S3-01, a SAM 2.1 calibration pass and a seven-arm development table are run once on the development set (PLAN S2-06).
- **Ruling 84-1 (b)**: one ReID projection head is pinned per `mask_source`; the SAM 2.1 table uses the head trained and selected on the SAM 2.1 cache, and within each table all arms still share the same projection byte for byte.
- Shared-source rules: descriptors, geometry, volumes, causal poses and admission rules are identical for both sources; one cache root stores only one source, the episode seal records the source (SAM 2.1 seals keep their original bytes), and the reading entry point rejects caches of the other source.

| Component | Specification | Output |
|---|---|---|
| Proposal (main table, ruling 72) | The pixel region of every registered label in the simulator's private per-frame instance map, each turned into an anonymous boolean mask; from the private record the generator reads only the frame index and frame digest (to check that it is the same frame as the public one), the instance-map file name, the set of label values and the instance-map pixels; it neither reads nor writes out the label values themselves, object IDs, types, poses, visible pixel counts or ground-truth boxes; admission is the same as for SAM 2.1 (≥196 pixels, ≤64 per frame, construction failure when exceeded, ordered by mask digest) | anonymous `fragment` masks |
| Proposal (second main table, ruling 83-3; a robustness appendix between rulings 72 and 83) | SAM 2.1 Hiera Small automatic masks; 15 of the 17 parameters registered by D-215 are unchanged, while `box_nms_thresh` and `crop_nms_thresh` are set to 0.7 (the reference value of the SAM 2.1 automatic mask generator) by D-224-S1 ruling 43 (the value 1.0 frozen by D-215 disables NMS; measured at about 500 masks per frame, 9/9 frames exceeded the cap of 64, so the two rules had no solution on real frames; the effective configuration and its digest are in the S1-03 contract); per frame ≥196 pixels and ≤64 proposals, and a 65th makes the whole frame a construction failure | anonymous `fragment` masks |
| Descriptor | DINOv2 ViT-S/14 (without registers, 384 dimensions): mean of the patch tokens within the mask, L2-normalised; S1 also extracts ViT-B/14 (768 dimensions) as the only optional upgrade, chosen once by separation on the development set and frozen before S3 (outcome: ViT-B/14 with the shared ReID projection, LOG-245 and LOG-261; see the ReID paragraph below); DINOv3 is not the default because its licence has not been checked | per-fragment vector |
| Geometry | depth + intrinsics + causal episode-relative pose → fragment three-dimensional points, centroid, AABB, pixel count, valid-depth ratio | per-fragment geometry |
| Free space | Set of voxels traversed by reliable depth rays, reliability gate `ρ_free` (null) | per-frame volume |
| Visible volume | Set of voxels inside the view frustum and in front of the depth surface | per-frame volume |
| Should-be-visible test (a per-point depth test since ruling 74; since ruling 75 it tests the entity's own surface points) | Ruling 75: the points tested are the surface of the entity as last seen — the depth-valid pixels inside the masks of the fragments of its most recent frame of evidence, back-projected to the world, at most 64 per fragment (in one-to-one correspondence with the union rule of the entity box) — rather than a grid inside the box, because most of a single-frame box is empty space, so present objects would be judged seen through; a ground-truth location has no surface of its own and still uses the grid inside the box. The original text of ruling 74: 64 sample points on the entity AABB are projected one by one into the current frame's public depth map (public intrinsics, causal pose): a measured depth more than 0.05 m beyond the point is "seen through", a difference of at most 0.05 m is "on the surface", nearer is "occluded", and a point outside the image or with invalid depth is "not observable". Visibility ratio = (seen through + on the surface) / 64; a ratio ≥ `v_min` means "should be visible in this frame"; free-space coverage = seen through / (seen through + on the surface), recorded as 0 when there are no observed points. A present object exposes only the layer facing the camera (about 1/4), whereas the original location of a removed object is seen through entirely (coverage 1). The voxel volumes of the two rows above remain in the cache but no longer take part in these two ratios | two ratios per entity |

**The per-entity geometric ratios are quantities derived online per arm, not cache fields.** The visibility ratio and the free-space coverage are obtained by querying the current frame's public visible voxels and reliable-ray voxels with the AABB of each entity in M_{t−1}; M_{t−1} differs between arms, so they cannot be written into the shared cache in advance. `entity_geometry` in the S0-03 contract is computed online by the S2-01 runner with one deterministic function shared by all arms, only from (public voxel sets, M_{t−1}), and is then fed to the assignment layer. Tests must prove that this function is a pure function of these two inputs; it must not read any private geometry (D-224-X).

**Shared ReID adapter head (D-224-E, optional front-end component).** The cosine of frozen DINO descriptors does not separate the same object seen from different views from different objects in the same scene; this was judged the bottleneck most likely to lower every arm's scores. The head maps a frozen descriptor (384 or 768 dimensions) to a 128-dimensional L2-normalised projection; its parameters are trained once with an instance-level contrastive loss on houses of the train split and then frozen, and **all arms share the same projection byte for byte**, so it is not a private advantage of VSMT-lean. Its separation is measured in S1-04 together with that of the original frozen descriptors, and S1-05 chooses one of the two by a registered rule and freezes it. It produces no fragments and makes no identity decision; its contrastive labels come from the same source as the main teacher but are used only on train houses; it does not count against any method's budget of 12 configurations. If it is selected, the paper must also report the frozen-descriptor baseline and must not report only the stronger front end. **Ruling 47 (2026-09-22)**: the output dimension 128 and the selection threshold of 0.05 in cosine are registered; the projection is trained only on the first 30 houses of the development cache in hash-prefix order, and S1-05 measures separation only on the last 12 and compares it with the frozen descriptor; the projection is selected only if its median cross-view separation is at least 0.05 higher, otherwise the frozen descriptor is kept. The two groups are disjoint, so separation is never measured on training houses.

**Outcome of the descriptor choice.** S1-05 selected `reid_projection:vitb14`, i.e. DINOv2 ViT-B/14 descriptors with the ReID projection (median separation gain 0.093 ≥ 0.05 on the SAM 2.1 development cache; the selection group had 9 rather than 12 houses because only 39 development caches succeeded, which ruling 59 kept; LOG-245). LOG-245 registers the frozen ViT-B/14 descriptor as the baseline to be reported alongside; ViT-S/14 is no longer read by the assignment layer. After the switch to instance segmentation, ruling 73 retrained the head on the instance-segmentation cache; S1-05 again selected `reid_projection:vitb14` (gain 0.104) and the new weights were re-pinned (LOG-261).

**Why the main table switched to instance segmentation (ruling 72, based on LOG-257 (cont.)).** On the same 4 development episodes, with the same runner/teacher/audit and only the fragment source changed from SAM 2.1 to simulator instance segmentation: TAF (θ_a 0.65, no gate) node F1 (IoU 0.3) 0.224 → 0.399, centroid criterion 0.434 → 0.540; the ratio of the total number of predicted entity-frames to that of ground-truth object-frames 3.19 → 2.42; ground-truth objects that "never produced a fragment" 4.0% → 0; in a grouping diagnostic that unites, by private identity, the boxes of all entities of the same identity (possibly from different times) into one, the IoU criterion 0.45 → 0.64 and the centroid criterion 0.76 → 0.86. The conclusion is that the over-segmentation and missed detections of SAM 2.1 are an important confounder unrelated to the memory method (this difference includes changes in the subsequent association trajectories and cannot be apportioned further; LOG-262 withdrew an earlier "accounts for half" reading); following the practice of DINO-WM (frozen pretrained features, a very small learned module and a deliberately simple environment), the main table uses unconfounded segmentation and leaves the method differences to stale entities, false retractions and identity continuity. **This does not reveal identities to the methods**: the cache contains no instance labels, and whether two fragments of the same object in two frames belong to the same entity is still inferred by the method from appearance and position; nor does it correct the geometric difference between the single-frame depth-surface shell and the whole ground-truth box (the grouping diagnostic above changes both the number of entities and the geometry and is not a strict upper bound — for LOW without a gate both columns even decrease after grouping; it only shows that the IoU secondary column is clearly limited by single-frame surface boxes: with the same predictions judged by centroid, TAF is 0.108 higher and LOW at 1.0 m 0.309 higher). **Limitation**: the conclusions of the main table hold only in the "segmentation known" setting; the SAM 2.1 front end is reported once on the same development houses as a robustness appendix, and the paper must state this alongside (superseded by ruling 83-3: SAM 2.1 is the second main table). The ReID projection head (ruling 47) was trained on SAM 2.1 fragments; by default its frozen weights are reused unchanged and only the recall curve is rechecked on the new cache; whether to retrain is a separate ruling (ruling 73 retrained it, LOG-261; ruling 84-1 (b) later pinned one head per mask source).

**The front end cannot explain the order of the arms (2026-09-29).** The seven arms read byte-identical clones of the same cache, so the fact that VSMT-lean's node F1 in the development table is lower than that of AssocOnly and LOW (LOG-270: 0.715 vs. 0.786, 0.732) cannot come from the front end, only from the memory logic; ruling 81 established that 41%–56% of the object-frames lost by the two learned arms are initiated by false bindings. The current instance-segmentation front end is an upper bound for segmentation, and SAM 2.1 segmentation can only be less accurate: on the same 4 episodes, TAF's node F1 (IoU 0.3) drops from 0.399 to 0.224 and the centroid criterion from 0.540 to 0.434, entities per ground-truth entity rise from 2.42 to 3.19, and 4% of the ground-truth objects never produced a fragment (LOG-257 (cont.)). The value of the second SAM 2.1 main table is to answer whether the conclusion survives real segmentation noise, not to raise absolute values. The levers for raising absolute values are the executor (direction B, ruling 83-2), the geometry of single-frame surface shells against whole boxes (LOG-244 (cont.) measured that accumulating united boxes is worse; rejected) and the descriptor; changing the descriptor requires re-freezing S1-03 and re-running all stages and is outside ruling 83. The side-by-side readings of S1-04 (basis of ruling 84): the median identity separation of frozen ViT-B/14 is 0.140 on SAM 2.1 fragments and 0.071 with instance segmentation, and the gain of the ReID head is +0.093 vs. +0.104, so the descriptor is not the weak point of SAM 2.1; the median IoU of fragments against ground-truth boxes is 0.45 vs. 0.67 for pickupable objects and 0.14 vs. 0.67 for containers and furniture, so the gap lies in part-level masks and missed detections. A revision of the mask layer (preferring whole-object masks) is deferred by ruling 84-6 until after the S2-06 readings.

The front end reports which anonymous fragments are present, where they are, which space is verifiably empty and which space is clearly visible in the current frame; it does not decide whether a fragment is the same object as one seen before. ## 6. Frame-level joint assignment

**Frame-level joint assignment** decides each frame jointly: the fragments F of the frame, the entities recalled for them by cosine and one virtual BIRTH column per fragment form one rectangular assignment, which, with per-entity existence decisions, is compiled into the frame program. A fragment binds to at most one entity, SPLIT/MERGE are not solved, and no private identity is read. This replaces the archived design that enumerated candidates by bucket, executed and scored each independently and took the maximum, which missed candidates, truncated capacity and allowed one atom per step.

Steps:

1. **Recall (union of two channels).** For each fragment f: the local channel takes, by descriptor cosine, the top `k` entities whose centroid distance is ≤ `R_local` (null); the global channel **treats active/dormant/retracted alike**, has no distance limit and takes the top `k′` (null) by cosine. The two are deduplicated and merged, with ties ordered by `entity_id`. The recall set, its order and its digest are sealed at this point. (Correction 2026-10-09: D-224-S1 ruling 57 (2026-09-24) froze `k` = 5, `k′` = 3 and `R_local` = 3 m in the S0-03 `recall_rule`, and ruling 58 (same day) froze the BIRTH neighbourhood radius at 1.0 m; ruling 90 (2026-09-30) kept `k′` = 3.) **Ruling 46 (2026-09-22)**: the four values `k`, `k′`, `R_local` and the BIRTH neighbourhood radius are frozen once after S1-04 reports the recall_miss curves on the development cache, are not changed afterwards, and do not touch validation/test; the "previous-frame memory" used by S1-04 to compute the curves is an **ideal memory** (one entity per ground-truth object, whose descriptor and centroid are the means over its earlier labelled fragments); it measures the recall ceiling of the front end, is independent of any arm and serves only as a diagnostic. The global channel ignores state because `AssocOnly` has no dormant/retracted states at all: if long-range eligibility were given only to these two states, its old entities would stay in place and be blocked by the distance gate into BIRTH, and the comparison would mix "whether there is a lifecycle vocabulary" with "whether there is long-range candidate eligibility", whereas D-224-HIJ requires a pure counterfactual of the former. Candidate eligibility is therefore independent of state and shared by all arms; the state only decides which atom an assignment compiles into.
2. **Cost matrix.** Rows are F sorted by `fragment_id`; columns are the union of the recalled entities plus |F| virtual BIRTH columns. `C[f,e] = −a(f,e)`, `C[f,birth_f] = −b(f)`. The negated logit is used instead of `−log σ(·)`: softmax training learns `p(column|row) ∝ exp(logit)`, and maximising the joint log-likelihood is equivalent to minimising `Σ(−logit)`, because the normalising constant is constant per row and does not affect the joint optimum; `−log σ` is a nonlinear monotone transform that changes the optimal pairing under competition across rows, and in tests about one in ten random two-by-two cases gave a different answer. Combinations outside recall receive a forbidding cost computed from the maximum/minimum legal cost of the current matrix and the number of rows, which guarantees that any assignment containing a forbidden cell is strictly more expensive; a fixed large constant is unsafe because extreme logits can produce equally large legal costs.
3. **Rectangular assignment.** An in-house solver finds the minimum total cost and normalises the result to **the lexicographically smallest optimal solution**; rows are ordered by `fragment_id` rather than by the order returned by SAM 2.1, so permuting the fragments of a frame cannot change the result among ties.
4. **Compilation.** f→active e is recorded as BIND; f→dormant/retracted e as REACTIVATE; f→birth as BIRTH.
5. **Existence decisions.** For every entity e that is `active` or `dormant`, should be visible in this frame and is unassigned (D-224-LQ ruling P; a `retracted` entity has no RETRACT/NOOP to decide and is not a candidate): σ(r(e)) ≥ `τ_r` (null; part of VSMT-lean's ≤12 configurations) records RETRACT; otherwise NOOP is recorded and the miss count is incremented.
6. **Commit.** The executor atomically executes all atoms on a clone of M_{t−1}; on failure the whole frame is rolled back and `illegal_program` is recorded; the shared dormancy rule and the shared deduplication then run on their registered schedules. A rolled-back frame cannot simply be skipped: the runner commits an empty program for that frame (the tick advances as usual, dormancy and deduplication run as usual) and counts `illegal_program` in the per-example failures; otherwise the next frame would be rejected with `frame_tick_not_next` and the whole episode would stall (D-224-X, implemented in S2-01).

**Why sealing has two stages.** Stage A seals the recall set and the association/birth features before any model runs and before any private file is opened. Stage B seals the assignment receipt and the existence features after the solve, because one existence feature is "whether the most similar fragment is still unassigned", which is undefined before the solve. Sealing only stage A would leave one third of the model inputs outside the invariance guarantee, and the statement "the three feature tables are byte-for-byte unchanged" would not hold. Only after both digests are written may the teacher open private; the assignment fed into the existence features during training must come from the current policy or from a registered rule-based arm and **must never be the teacher's assignment**, otherwise the student would see during training something it cannot obtain at deployment.

## 7. Learned cost heads

The three **learned cost heads** are the only trained component of VSMT-lean apart from the frozen ReID projection shared by all arms (Section 5). Each combines the public per-pair or per-entity features of the table below into one scalar logit for association, existence or birth; the heads are not an end-to-end visual network, do not process images, produce no fragments and see no future frame.

| Head | Input features (all computed from the public cache and M_{t−1}) | Output |
|---|---|---|
| Association head a(f,e) | cosine to `descriptor_mean`; cosine to `best_view_descriptor`; centroid distance; three-dimensional AABB IoU; log size ratio; `t − last_seen_t`; `missed_opportunity_count`; state one-hot; cosine rank of e within the recall of f; gap to the second-best cosine; whether f and e are mutual best matches; supporting-surface height difference | association logit |
| Existence head r(e) | visibility ratio; free-space coverage; camera-to-centroid distance and viewing-angle cosine; `missed_opportunity_count`; `observation_count`; `t − last_seen_t`; highest cosine to any current fragment and whether that fragment is still unmatched; state one-hot; **five history-summary features (ruling 89-2)**: two "consecutively seen through" counts (coverage ≥ 0.70 / ≥ 0.85, reset on a match), the number of matches since birth, the number of decidable frames, and the accumulated free-space coverage | "no longer at its place" logit |
| Birth head b(f) | highest cosine to any entity; number of active entities within 1 m; fragment pixel count; valid-depth ratio | birth logit |

**Method definition (ruling 99-1, 2026-10-01; the version frozen in S2-R and evaluated on the development and confirmation sets; S3 trains accordingly).** Input widths: association 14, existence 17, birth 4. Architecture: each head first encodes each field (count fields take log1p and are then standardised with the mean and standard deviation recorded on the training houses; no learnable parameters; this replaces the former input LayerNorm), followed by a two-layer, 128-wide GELU MLP with a one-dimensional output; the three heads of VSMT-lean have 54,787 parameters in total (association 18,561, existence 18,945, birth 17,281), and the two heads of AssocOnly 35,842. Loss: a per-fragment softmax cross-entropy over `[recalled columns…, BIRTH column]` (one term shared by the association and birth heads), plus a per-entity binary cross-entropy for existence in which gone rows are weighted by w = number of present rows ÷ number of gone rows in the training records (about 65 in round 1); the two terms are added. The existence decision is sigmoid(existence logit − ln w) ≥ τ_r, with τ_r 0.5 for both the development and the confirmation readings. The encoding statistics and w are computed only from the records of the training houses; the selection houses are used only to score checkpoints. Recipe: AdamW, weight decay 1e-4, per-frame batches, 20 epochs, learning rate decayed per epoch with a cosine schedule from 1e-3 to 1e-5, gradient-norm clipping at 1.0 over all heads jointly at every step, seeds 7/19/31/43/59. The distribution shift of causal memory is handled by two rounds of DAgger: round 0 trains on the records produced by ELU-P at the cell of the `rollout_config` pre-registered in S0-05 and selects the checkpoint by the total held-out loss; round 1 uses the round-0 ELU-P records plus the records produced by this arm's own round-0 heads, concatenated in full without resampling, with **grouped selection**: the association and birth heads together take the epoch with the lowest held-out loss of the association term, the existence head the epoch with the lowest held-out loss of the existence term, ties going to the earlier epoch; the main table uses round 1. Grouped selection in round 0 was never evaluated and is not part of this method. The machine record is S0-05 `arms.VSMT-lean.training.s2r_recipe`; the current implementation entry point is `ops/vsmt/ruling89_train.py --revision-91 --group-selection`, and the formal S3 training entry point must use this recipe by default (implemented and tested when preparing S3-03). (Correction 2026-10-09: the formal S3 training entry point is `ops/vsmt/s3_03_train.py`, which takes this recipe from `lean_s3_03.training_settings`; `ruling89_train.py` remained the development-stage entry used by S2-06.) The recipe originally registered in S0-05 (constant learning rate, input LayerNorm, 12-dimensional existence head, unweighted existence term, checkpoint selection by a single total loss, 54,207 parameters in total) is the recipe of the runs before ruling 89; their reports remain bound to the contract bytes and code commits of that time. The labels of `HeuristicLabel` still come from that `rollout_config` cell (D-224-X ruling X4). The heads accept no slot, path, sample name or house ID as input.

The model is deliberately small (frozen visual features, cost heads with 54,787 parameters in total and one Hungarian assignment per frame) and is neither a VLM nor a graph network: there are only on the order of a hundred thousand training decisions, the competing methods are all training-free, and the gain of any large model could not be separated from that of the front end.

## 8. Instance-truth teacher and information boundary

The **instance-truth teacher** labels the sealed recall set and feature matrices from the private instance ground truth at time t: one target column per fragment and one "no longer at its place" label per entity. A fragment is a BIND positive when its dominant instance ID equals the majority instance ID of the entity's provenance; an entity is a "no longer at its place" positive when its instance has been removed, or when, by the location rule of the primary node column, the entity is no longer at its object (ruling 88-4). The teacher generates no candidates, does not change the recall set and takes no part in deployed inference. It replaces the archived design, which could score only after future observations and in which most semantics could not be fixed in advance.

Gates that must all hold; the failure of any one stops the work:

1. Deployment-visible inputs contain only public RGB-D-derived quantities at or before the decision time, causal poses, action summaries and M_{t−1}; house IDs, simulator object IDs, ground-truth masks and intervention logs do not enter model values.
2. The recall set, the feature matrices and the BIRTH columns are computed and their digests written before any private file is opened; the teacher reads only the fixed rows and columns that this digest points to.
3. When any private file is modified while the public bytes stay unchanged, the recall order, the feature matrices and the logits of an untrained model remain byte-for-byte unchanged.
4. The evaluation process completes all predictions while private is invisible; the evaluator then opens the labels independently, according to the prediction digest.
5. A correct entity missing from the recall set is recorded as `recall_miss`; a wrong label as `teacher_error`; a disagreement between the student and the label as `amortization_error`.
6. A nuisance probe using only paths, seeds, frame indices and house indices must not predict any label.

**S0-04 implemented the boundary above as a machine contract and testable code (LOG-217; criteria frozen by D-224-LQ).** Private data can be opened only with a release receipt that records both the stage-A and the stage-B seal digests; if either is missing, opening is refused; the teacher does not open files itself and does not add, remove or reorder recall entries. An entity's identity is the **strict majority** (more than half) of all its evidence that carries an object; without a strict majority it is ambiguous; there is no second threshold, and background evidence does not vote; ambiguity is only counted, never guessed (ruling N). A fragment's dominant object is first determined from the instance overlap table, with all pixels of the fragment as the denominator: no object gives `unlabelled`; covering two or more objects with the largest share below `dominance_min_share` (null), or tied, gives `identity_ambiguous`; covering only one object with an insufficient share gives `unlabelled`. Once the dominant object is established: if the memory has no entity for the object, `birth`; if it has one but it was not recalled, `recall_miss`; if it has one and it was recalled, the target entity is given (among duplicate entities, the one whose first version is earliest, ties by smallest ID; if only a duplicate was recalled, the recalled one is the target; `retracted` entities are legal targets); if the evidence of the object lies only in entities with ambiguous identity, `identity_ambiguous` is recorded rather than guessing birth. Existence labels are given only for `active` and `dormant` candidates (ruling P): if the object is no longer in the scene, `gone`; if the object is present, `gone` is recorded only when the entity fails, for its own object, the location rule of the primary node column (centroid within `δ_moved` of the object centroid, or inside the ground-truth box enlarged by 0.25 m; ruling 77), otherwise `present`. **Ruling 88-4 (2026-09-29)** replaced the earlier centroid-only rule (ruling Q) with the same yardstick as the primary node column: under the old rule, 28.9% of the `gone` labels in the development trajectories fell on entities that were still in place by the primary node column and had no other carrier (when only one side of a large object is seen, its surface centroid is off-centre), whereas real removals or moves after the window accounted for only 13.3%; duplicate entities in place are therefore labelled `present`, and the redundancy is left to the shared deduplication. The old rule is kept as the named diagnostic criterion `centroid_only`, used only for the decision-ceiling comparison of ruling 88-2. The three-way decomposition (the ledger of the paper) is booked per frame and is mutually exclusive and additive: `recall_miss` is not charged to the student; `teacher_error` is an ambiguous label; `amortization_error` is a clear label with the candidate present and the student still choosing wrongly, including false retractions and missed retractions; unlabelled fragments are counted separately, and the five classes sum to the number of decisions. The assignment fed into the existence features during training comes from the current policy or from a registered rule-based arm; the teacher produces no assignment. **Duplicate fragments in the same frame (D-224-X ruling X1).** SAM 2.1 often splits one object into several pieces; if two pieces of the same frame are both judged to be the same object with the same target entity, the second can never be satisfied, because the executor lets an entity receive only one fragment per frame, and recording it as an amortization error would charge a structural impossibility to the student. Therefore only the piece with the most pixels on the object (ties: more pixels in the whole piece, then the smaller fragment_id) keeps the target; the others are recorded as `duplicate_of_labelled`: they do not enter the loss, are not recorded in any error class and are counted separately, and the six classes sum to the number of decisions. Fragments with different targets, with the birth column as target, or that are recall_miss are not folded. Booking is per group (review revision, LOG-225): the kept piece and its duplicates are judged together; if any piece of the group is assigned to the target entity and no piece is bound to another existing entity, the kept piece is recorded as correct, otherwise one amortization_error is recorded; which piece of the group is bound does not matter. **The ground-truth table carries an `in_scope` flag (ruling X6).** The table received by the evaluator contains all private objects to which entity evidence can be resolved; the scope rule is applied by the evaluator, and entities resolving to out-of-scope objects are counted separately instead of causing a crash; entities corresponding to present but out-of-scope objects are also removed from the precision denominator and only counted, while entities whose object is absent remain in the denominator and count as stale (review revision, LOG-225).

## 9. Controls

The four controls share with VSMT-lean the same frozen front end, the same recall rule, the same shared deduplication and dormancy rules, the same executor and the same evaluator; they differ only in how the cost matrix and the existence decisions are produced. All rule-based arms are gradient-free and choose only within a pre-registered finite grid; each method has at most 12 complete configurations, VSMT-lean included; each method selects its single configuration on validation by node F1, and the primary-gate metrics take no part in selection (D-224-SW ruling V); ruling 102-4 adds one identical threshold for the six arms with a retraction mechanism (VSMT-lean, NoVersion, HeuristicLabel, HandCost, ELU-P, RAC): selection is restricted to configurations whose validation Missing residual rate is below that of AssocOnly on the same front end (learned arms and AssocOnly use the mean over 5 seeds); if no configuration satisfies it, the configuration with the highest node F1 is taken and "constraint unsatisfiable" is recorded; its numbers are computed as usual but do not support "this arm's retractions reduce stale entities" (`lean_arms.select_configuration`). Inside the gate, rule-based arms give graded costs (cosine or negative centroid distance) and outside the gate the registered sentinel logit; the distance-gate grid of every rule-based arm must contain a no-gate option (D-224-R); existence candidates are unassigned entities that are active or dormant and whose visibility ratio is not below the shared minimum (ruling W).

| Arm | Mechanism source | Costs and existence decisions | Not to be claimed on this basis |
|---|---|---|---|
| `TAF` | ConceptGraphs-style threshold association and fusion | BIND cost 0 if cosine ≥ θ_a and distance ≤ d_a, otherwise +∞; constant BIRTH cost; no retraction | official ConceptGraphs |
| `ELU-P` | Fusion++ existence log-odds plus Perpetua-style persistence filtering | association as in TAF; existence log-odds decrease with reliable free-space coverage and increase with matches; emergence/persistence rates fitted only on train; RETRACT when the gate is crossed, REACTIVATE on a new match | equivalence with the full upstream systems |
| `RAC` | DSG-style render-and-compare | association as in TAF; the entity AABB/points are projected into the current depth map; a share ≥ `ρ_rac` of pixels whose observed depth exceeds the memory surface by more than `margin` counts as one piece of negative evidence; RETRACT after `n_rac` consecutive ones | official DSG or Gaussian rendering |
| `LOW` | last-observation overwrite | attributes are overwritten if the nearest centroid distance is ≤ d_low, otherwise BIRTH; no retraction, no reactivation | deliberately weakened control |
| `LLM-op` (mandatory appendix arm) | Mem0-style training-free operation selection | the same feature tables are converted to text, and a frozen LLM chooses BIND/BIRTH/REACTIVATE/RETRACT/NOOP row by row | must not enter the main table; appendix results cannot serve as the main comparison (registered as an appendix arm; the paper has no appendix and reports it in Table III, outside the test comparison) |

The thresholds of each rule-based arm may be selected only on the S3 train/validation splits; values published for other datasets are not copied.

**The status of `LLM-op` is settled (D-224-HIJ).** It changes from "optional, conditions unclear" to a **mandatory appendix arm**: it must be run, but only on validation, and its results enter only the appendix, never the main table. It tests whether a training-free LLM already suffices: it reads a text rendering of feature tables byte-identical to those read by the other arms and returns one operation per row. It is placed in the appendix rather than in the main table because its cost and its prompt sensitivity make the fair budget of "at most 12 complete configurations per method" inapplicable to it; putting it in the main table would amount to a comparison along a dimension whose budget cannot be aligned. It is not a weakened control and does not imply that this project considers the LLM route ineffective; promoting it to a main-table arm later would first require freezing its own configuration-budget criterion and would be a new ruling.

**Calling protocol of `LLM-op` (ruling 105, 2026-10-04).** The model is DeepSeek `deepseek-flash` (V4.1-Flash on that date) in the provider's default reasoning mode (only thinking is switched on explicitly; all other parameters at their defaults), run once; each of the two front ends runs the same validation episode (position 1 in ascending order of the sha256 of the salt string plus the episode ID; ruling 108 changed this from 15 episodes to 1, as the appendix makes only a descriptive comparison without significance testing). The existence features exist only after the association solve, so each frame is queried twice: first, seal A is written as two tables with headers (recall pairs with 14 features, birth options with 4 features), asking for one row per fragment stating which candidate or BIRTH it chooses; the choices become logits for the same solver (chosen pair 0, other recall pairs the sentinel, BIRTH 0 if chosen and −1 otherwise); after the solve, the decidable entities are written as one table, asking for one row per entity with RETRACT or NOOP. The instructions contain only the task description, the definition of each column and one artificial format example, with no thresholds, statistics or examples from the data (training-free); the digest of the text is pinned in the contract `lean_s3_03_llm_op_v1.json`. Each call allows at most three answers; if all three are invalid (empty, truncated, filtered or unparseable), the call falls back to BIRTH for all fragments and NOOP for all entities and the fallback is counted; if the fallback rate of a front end exceeds 2%, the appendix marks it "format unreliable". Every answer is archived before use, and re-runs replay from the archive; a pass accepts only one returned model name. The arm does not train, does not select configurations, does not enter the main table and does not read test; its results are compared with the other arms only in the appendix, on the same episode. Paper wording (registered 2026-10-07; formulation in PLAN section 7): a descriptive single case only (n=1 per front end, no significance test); this episode was fixed by the registered draw rule before any LLM call, and the original list of 15 was written down before the run and kept; it has no identity or retrieval events, so only node-type metrics are compared; whether it is "unusually hard" is judged from the percentile of each other arm on this episode within that arm's own full validation distribution, not from the score of LLM-op itself.

## 10. Ablations

| Name | Exact definition | Question answered |
|---|---|---|
| `NoVersion` | RETRACT becomes physical deletion; a deleted entity no longer exists in memory and therefore cannot be recalled, and a reappearance can only be a BIRTH; the recall rule, cost heads and training are unchanged | what reversible versions are worth for the identity continuity of moved objects |
| `HandCost` | the three cost heads are replaced by hand-written scores without temporal accumulation: cosine for association, a constant θ_b for birth, the current-frame free-space coverage passing ρ_h for existence; the solver, executor, vocabulary and reactivation rule are those of VSMT-lean (D-224-SW ruling S) | the contribution of learned costs relative to hand-written costs under the same decision structure; ELU-P separately answers what "probabilistic forgetting with temporal accumulation" is worth |
| `HeuristicLabel` | the public decisions of ELU-P at the pre-registered `rollout_config` cell are used as labels, and the same network is retrained with the same recipe (D-224-SW ruling T; D-224-X rulings X3/X4; TAF never retracts, so the existence head would have no gone samples to learn from). The three fitted quantities of ELU-P are estimated on train private ground truth; the only private dependence of these labels is these three scalars, and the contract states this sole dependence instead of claiming that only public data are used (review revision, LOG-225) | the contribution of private instance ground truth relative to public heuristic labels |
| `AssocOnly` | the same learned association head and the same solver, but the transaction vocabulary is reduced to `BIND` and `BIRTH`: no retraction, no reactivation, no dormancy; the `retracted` set does not exist | what the lifecycle vocabulary itself is worth, as opposed to the learned association |

The four ablations share the same front end, data, recall rule, training budget and evaluation; an ablation that has been removed may not be added back after test has been seen.

**Implementation of rulings 99-1/99-3 (2026-10-01) for the ablations.** `AssocOnly` uses the association-side recipe of the method definition in Section 7 (same encoding, learning rate, gradient clipping and two rounds of records); it has no existence head and no existence term, only the association group, so both checkpoint-selection rules give the same result for it; `NoVersion` uses the heads of VSMT-lean and only switches the runner's deletion flag; `HeuristicLabel` uses the same recipe and changes only the label source; `HandCost` is not trained. Although `AssocOnly` is an ablation in implementation, the main table must report it alongside the five main comparison arms; `NoVersion` separately tests the effect of version retention itself, and neither can substitute for the other. `VSMT-lean-ctx` leaves S3 (the description of the optional arm below is kept only as a historical record).

**`AssocOnly` is the direct counterfactual of claim 1 (D-224-HIJ, mandatory).** It separates the effect of learned association from that of the retractable and reactivatable lifecycle vocabulary. It reads input byte-identical to that of VSMT-lean and emits only the two operations BIND and BIRTH; `HandCost` changes the source of the costs and `NoVersion` the reversibility, and neither answers what the vocabulary itself is worth. For a moved object, VSMT-lean can RETRACT the old entity and REACTIVATE it elsewhere, whereas `AssocOnly` keeps the identity only by binding the new fragment to the old, still active entity; otherwise it keeps the old entity and births a new one at the new place, producing a stale entity and a duplicate at once. Because it is the only causal counterfactual of contribution 1 in Section 2, **the main table of the paper must report it alongside the main comparison** and must not place it only in the ablation table. It is not a rule-based arm and is not TAF: TAF's association uses hand-written thresholds, whereas `AssocOnly`'s association is the same learned head. "The same learned head" means the same architecture, recipe and budget and the same two rounds of DAgger, retrained on its own memory trajectories with the existence loss term removed; it **does not reuse the trained weights of VSMT-lean**: reuse would change the whole input distribution (the state one-hot is always active, the miss count always 0) and mix a distribution shift into the counterfactual (D-224-X ruling X3).

**`VSMT-lean-ctx` (D-224-F, optional arm, not the default).** The cost heads score each candidate pair independently and cannot see joint constraints such as "fragment f1 already holds entity e1, so f2 should not also claim e1". In this arm the features of all fragment × candidate-entity pairs of the same frame attend to each other through 1–2 transformer layers before the same three scalars are output; the solver, executor, teacher and metrics are unchanged. It is registered as an optional arm rather than a main-table arm: the experience of S5 is that a Set Transformer did not change the conclusions relative to an MLP, and a scale of 300 houses carries a risk of overfitting. The main table is always based on the MLP version; the ctx version shares the same training budget and configuration quota as the MLP version, its results are reported separately, and it may not replace a main-table row after test has been seen.

| False-retract rate (FRR) | Among RETRACTed entities, the share whose ground-truth object is still in place ("in place" by the location rule of the existence labels, i.e. the rule of the primary node column, ruling 88-4; earlier development-table values used the old centroid-only rule and are not comparable); for arms that never retract it cannot be computed by construction and is reported as not applicable, entering neither pairings nor exclusion lists (review revision, LOG-225) | this project |
| Identity continuity (IdC) | Since ruling 102-0 (2026-10-02): all arms are scored on the same events — moved objects, at the first time after the window that a fragment has them as dominant object (determined only by front-end fragments and private labels); the event counts as kept if this reappearance is assigned (BIND/REACTIVATE) to any entity that carried the object at the last frame of the window; an arm that had no carrier entity before the move also counts as not keeping it; the `canonical_of` folding of deduplication is not recognised (ruling M). Reported fields `kept`, `events`, `no_prior_carrier` | this project |
| Identity continuity, conditional column (diagnostic, `identity_continuity_conditional`) | The definition before ruling 102-0: only events in which the arm had a carrier entity before the move are counted (`judged`), so denominators differ between arms (of 63 reappearance events on the SAM 2.1 development set, VSMT-lean seed 7 counts 49 and LOW only 24); reported alongside the primary column, not in the primary gate and not used for selection | this project |
| Recovery latency | Number of frames from when the intervention site first becomes observable to the method until the memory state is correct (ruling O); unrecovered and never-observable cases are listed separately | this project |
| Contamination AUC | Trapezoidal area of the per-frame (stale entities + wrongly absent objects) / (entities in memory + wrongly absent objects), normalised to [0,1] | inherited |
| Scale and cost | Number of active entities, number of lifecycle versions (excluding the per-observation versions opened by BIND; ruling X6), runtime per frame, peak memory | inherited |

**Retrieval success (the eighth metric; registered by ruling 83-5, defined by ruling 102-5, frozen 2026-10-02).** Node F1 and MRR describe the memory itself; retrieval success adds an evaluator-built query on the same events (not a task result, Section 12). The events are the same as for identity continuity (moved objects, at the first time after the move that a fragment has them as dominant object; the same set for all arms); the query is built by the evaluator from private labels as the mean descriptor (the projected descriptor selected for that front end) of all fragments having the object as dominant object up to and including the last frame of the window, and is not visible to the methods; an object with no such fragment before the move is not an event and is counted separately (`no_query`); the candidates are all `active` and `dormant` entities in the memory after that frame's commit, and the most similar by `descriptor_mean` cosine is taken (ties: the smaller entity_id); an empty candidate set counts as a failure (`empty_candidates`); success is recorded if that entity matches the object under the pairing rule of the primary node column (majority identity is the object, and the centroid is ≤ δ_moved or inside the ground-truth box enlarged by 0.25 m). It is not in the primary gate and not used for selection; it differs from identity continuity, which asks only whether the new observation was attached to the old identity.

**Selection constraint (required by ruling 83-1, text fixed by ruling 102-4, frozen 2026-10-02).** Selecting τ_r by node F1 alone could favour retracting too little (ruling 79-7). The constraint therefore selects, per arm and from the validation metrics of all its configurations, the single configuration that enters test: the six arms with a retraction mechanism take the maximum node F1 only among configurations whose validation Missing residual rate is below that of AssocOnly on the same front end (learned arms and AssocOnly use the mean over 5 seeds; ties go to the smallest configuration number); the threshold is the same number for all six arms, with no per-arm counterfactual, no reference to the results of rule-based arms and no use of identity continuity; if no configuration satisfies it, the configuration with the highest node F1 is taken and "constraint unsatisfiable" is recorded; its numbers are computed as usual but cannot support "this arm's retractions reduce stale entities". TAF and LOW have no retraction and AssocOnly has no configurations to choose from; they select by node F1 only. Judging from the development readings, the constraint rarely binds; the concern originally raised by 79-7 about the Missing residual rate relative to the rule-based arms is handled by per-metric reporting. It does not read test.

The node matching of the evaluator is its own matching implementation (maximum cardinality first, then maximum weight; ruling 76 (3)(a)), **deliberately not reusing the method's assignment solver**, and it has been checked against brute-force enumeration; thus a bug in the solver cannot hide in the numbers that judge it, and the evaluator reads no surface ID. Recovery latency is averaged only over recovered objects; unrecovered objects are listed separately and do not enter the mean. No quantity other than the seven metrics, their registered secondary or diagnostic columns (node IoU column, in-scope false-retract rate, conditional identity-continuity column) and the eighth metric (retrieval success, ruling 102-5) may be computed or reported; scale and cost (number of active entities, number of lifecycle versions, runtime per frame, peak memory) is the seventh metric. The relation of the primary and secondary columns to Dyn-THOR must be stated in the paper: both columns use the same matching mechanism and differ only in the overlap criterion, and the centroid primary column is not Dyn-THOR's original criterion (ruling 72 (B)). The evaluator's matching is solved separately for each connected component of non-zero weights, which gives the same number of matches and the same total weight as solving the whole matrix and reduces a single frame from seconds to milliseconds (D-224-X ruling X5). Statistics use the house as the pairing unit, with 10,000 bootstrap draws and seed 20261002 (registered by ruling 102-3); **primary gate (ruling 99-2, a prospective revision of 2026-10-01; the revision took place after the development and confirmation sets and before validation/test were read)**: the primary hypothesis is that VSMT-lean, relative to the same-recipe `AssocOnly`, has one-sided 95% lower bounds above 0 for both MRR and identity continuity (i.e., the incremental value of the lifecycle mechanism); a non-inferiority margin for node F1 is frozen only if S3-01 can provide an independent, interpretable basis for a practical tolerance; otherwise only the difference and interval are reported, with the trade-off stated, and no non-inferiority claim is made. The original gate (VSMT-lean against the strongest control, one-sided 95% lower bounds of both MRR and identity continuity above 0) is computed as originally written and reported: it was not met on the development and confirmation sets; S3 is judged by the actual result and is not decided in advance. **Statistical details frozen by rulings 102-2/102-3 (2026-10-02); the S0-04 `statistics` block has been revised in place (`lean_teacher.primary_gate`)**: each metric and each front end has exactly one exclusion list — a house is excluded for all arms and all tests whenever the metric cannot be computed on it for any seed of any main-table arm (VSMT-lean and AssocOnly 5 seeds each; TAF, ELU-P, RAC and LOW one run each); the object of inference is the training procedure under fixed training data, recipe and selection procedure; the lower bound uses a two-level bootstrap (each draw independently resamples seed indices and houses with replacement, all drawn seeds share the same set of houses, and the two arms are paired by seed index), and in addition the 82-1 seed-stability condition is required (all five seeds present, at least 4 paired differences favourable, mean larger than the standard deviation of the 5 differences); a metric holds only if both conditions are met; whenever a learned arm lacks the run of one seed, any judgement involving it is recorded as "undecidable". With five seeds the coverage of the two-level lower bound has no theoretical guarantee; the null-effect calibration is in `results/vsmt_lean_s3_01_planning_6c57903.json` (two-level bootstrap plus 82-1 has a false-positive rate of about 5% for seed standard deviations 0–0.10, while house-only resampling can reach 0.17–0.33). `main_gate_effect_size` only registers the effect used for planning and is not a threshold; node F1 has no independent basis for a tolerance, so no non-inferiority margin is set and only the difference and interval are reported. The two main tables are tested in a fixed order (`lean_teacher.fixed_sequence`): (1) instance segmentation, both metrics together; (2) only if (1) holds, the Missing residual rate under SAM 2.1 is tested; (3) only if (2) holds, identity continuity under SAM 2.1 is tested; testing stops at the first step that does not hold, and "holds across both segmentations" is said only if all three steps hold; this split was designed after the S2-06 development readings had been seen and was frozen before validation/test were read. The original gate is computed with the same lists and rules and is only reported; the intervals of the comparisons with rule-based arms and of the ablations are descriptive only. When a metric cannot be computed for a house (for example, no object was moved and then revisited, so the value is null), that house is excluded on that metric for all arms and the number of valid houses is reported; the value is never filled with 0 or 1, and the power budget of S3-01 is computed on the valid number (ruling X2); the strongest control is taken per metric on the same set of valid houses, which on test is the post hoc maximum over the four controls and is conservative for the method. All metrics are reported separately and are not combined into a single overall score; test is run only once, and after the run no metric, threshold, data or control may be changed. The exclusion list for undefined houses is computed for a metric only over the arms for which the metric is defined by construction; arms for which it is undefined by construction are reported as not applicable on that metric; otherwise the three arms that never retract would make the whole false-retract column unreportable for every arm (review revision, LOG-225).

**Why the executor has a separate core instead of a narrowed `GraphRevision`.** `GraphRevision` and `cpmt.executor.validate_graph` were bound to the place scaffold, the five types of relation edges, `graph_hash` and the unified-graph lifecycle; narrowing them would have brought all of these along, contrary to the purpose of the D-224 reduction. The entity-memory core is therefore a self-contained module that reuses only pure functions that cannot introduce a second numerical semantics: canonical JSON and deep copy from `cpmt.hashing`, and cosine similarity, centroid distance and opaque IDs, copied verbatim into `lean_geometry.py` by D-224-S1 ruling 9 (they were first imported from `vsmt.graph_ops`, which pulled the archived graph code into the current entry points). `tests/test_vsmt_lean_geometry.py` pins the copies to the values `graph_ops` returned and checks at import time that no lean module loads the archived code.

**The solver was registered in S0-03 as an in-house implementation; no dependency is added.** scipy is not among the dependencies of this project, and ties must be decided by the project itself: a rectangular assignment usually has several optimal solutions, and which one is returned must not depend on dict ordering, floating-point noise or the library version. The implementation is a shortest-augmenting-path method with potentials, of complexity `O(rows^2 × columns)`, with ties always going to the smaller column index; since every fragment has its own BIRTH column, the number of columns is never smaller than the number of rows. The lexicographic normalisation was changed after D-224-X ruling X5: v1 re-solved the whole matrix for every column tried, which, measured locally, took 1,337 sub-solves and 1.2 seconds for 30×100 floating-point costs and 13,055 sub-solves and about two minutes for 64×500, whereas the original solve takes only a few milliseconds; v2 uses the optimal potentials (u, v) at the end of the original solve — by complementary slackness an optimal assignment can only use cells with zero reduced cost, and columns with negative potential must be matched — so it tries the smallest column row by row only on this sparse equality subgraph and uses two augmenting-path matchings to decide whether the remaining rows can still be completed (Mendelsohn–Dulmage guarantees that both conditions can be satisfied simultaneously); 64×500 drops to 0.01 seconds. The returned columns are identical to those of v1 column by column; the tests keep the v1 implementation verbatim as a reference for exact comparison, and in addition 40 random matrices are compared one by one with the lexicographically optimal solution from brute-force enumeration. It is not faster than scipy; it only guarantees that the same matrix always yields the same set of column indices.
