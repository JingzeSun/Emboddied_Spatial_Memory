# HC-025：节点出生、确认与再激活

状态：BLOCKED_BY_HC-024

## 要决定什么

一个 `NEW` region 何时只进入 candidate，何时创建 persistent node；如何避免重复节点和漏掉真正新区域。

## 不变量

- `NEW` association 不等于立即 `CREATE` persistent node。
- 单帧低可靠观测不能不可逆扩张世界图。
- 任何 birth 都要保存 origin evidence 和 parent attachment。

## 选项

| 选项 | 确认策略 | 权衡 |
|---|---|---|
| A（建议） | 证据累积的 delayed confirmation；高可靠 portal/frontier 可快速通道 | 控制重复 birth，同时保留具身实时性 |
| B | 单帧超过阈值即创建 | 快，但 pose glitch/短暂动态会污染图 |
| C | 固定 N 帧一致才创建 | 简单，但与速度、遮挡和视角相关，反应迟缓 |

## 建议落点

采用 A。candidate 有独立 ID、TTL、evidence bank 和 proposed attachment；满足跨视角一致、投影一致或可信 frontier 条件后才升格。对 inactive node 先检索 `REACTIVATE`，再考虑 birth。

## 必须记录

- confirmation score 的证据构成，而非只有总分。
- max candidate age、prototype capacity 和冲突处理。
- 快速通道适用的 node type 与撤销政策。
- birth 后若被发现重复，使用显式 MERGE transaction，不静默改 ID。

## 接受测试

S03 的 G1 recall 不因延迟策略崩溃；S04/S11 的 B4/G4 明显优于单帧 birth；重现旧节点优先 REACTIVATE。
