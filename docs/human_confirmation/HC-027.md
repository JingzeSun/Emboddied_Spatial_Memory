# HC-027：生命周期、可见性与动态层

状态：BLOCKED_BY_HC-026

## 要决定什么

如何区分 visible、occluded、out-of-view、inactive、removed 与 transient；何时撤回事实。

## 不变量

- 未检测到不等于不存在。
- occluded/out-of-view 不能触发 location 撤回。
- 动态 track 不自动融合进静态 surface/portal。

## 选项

| 选项 | 生命周期 | 权衡 |
|---|---|---|---|
| A（建议） | 显式 visibility model + node lifecycle state machine | 可审计，适合 absence evidence 和 revision |
| B | 统一 confidence decay | 简单，但把遮挡、离视野和移除混为一谈 |
| C | 完全 learned latent lifecycle | 灵活，但早期很难定义失败和硬约束 |

## 建议落点

采用 A。状态至少为 candidate、active/visible、occluded、out_of_view、inactive、retired、quarantined。`removed` 是版本事实或 RETRACT 结果，不等同于删除历史 node。

## 动态政策

- 未确认动态观测先进入 transient track。
- 可移动对象可升格 persistent slot，但 location fact 可版本更新。
- 行人等短时 agent 默认不进入静态结构图，仅作为 occlusion/evidence。
- 可靠 absence 需要 expected-visible、传感器有效和足够观测机会三者同时成立。
