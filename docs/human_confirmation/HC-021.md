# HC-021：线上输入与 oracle 边界

状态：BLOCKED_BY_HC-020

## 要决定什么

模型在线可见 RGB、depth、内参、位姿/里程计、动作中的哪些字段；哪些字段只能用于离线 oracle。

## 不变量

- `oracle_world_node_id`、模拟器 object ID、真实未来帧禁止作为线上输入。
- 输入位姿若来自 ground truth，必须另做 noisy/estimated pose 结果。
- absence evidence 必须基于可见性模型，不能把“没检测到”直接当移除。

## 选项

| 选项 | 在线输入 | 研究含义 |
|---|---|---|
| A（建议） | RGB + depth + K + noisy/estimated pose + action | 先隔离 memory/binding 问题，并可系统注入几何噪声 |
| B | RGB + K + odometry/action，无 depth | 更难、较接近部分平台，但投影误差与方法误差耦合 |
| C | RGB + action，学习隐式几何 | 最一般，也最容易变成另一个大规模 world model 项目 |

## 建议落点

首篇采用 A，必须报告 pose/depth corruption 与去 depth 消融。准确位姿只作为 O0/oracle 上界，不进入主结果。

## 必须冻结的字段

- 坐标系、单位、时间戳与同步容差。
- 位姿来源及 covariance。
- depth 缺失值、有效范围和插值政策。
- action 表示及执行/观测时间关系。
- tokenizer 是否看到未来或相邻帧。

## 接受测试

自动扫描训练 batch，任何 oracle-only key 出现即失败；manifest 明确列出 online fields。

pose_source: null
