# HC-031：指标、门槛与统计

状态：BLOCKED_BY_HC-030

## 要决定什么

哪些指标是主结果，如何阻止 precision、coverage、节点增长或更新幅度之间互相掩盖。

## 不变量

- 不用单一加权总分替代 B/G/M/R/P 分解。
- `UNRESOLVED` 必须与 coverage-risk 一起报告。
- test 不用于门槛、早停、prompt 或方法选择。

## 选项

| 选项 | 判定方式 | 权衡 |
|---|---|---|---|
| A（建议） | 顺序 gate + 主指标面板；所有 gate 通过才进入下一阶段 | 防止一项高分遮住 identity/birth 灾难 |
| B | 预注册加权综合分 | 排名简单，但权重任意且可被 gaming |
| C | 只报任务成功率 | 对应用直观，但无法证明 memory 机制 |

## 建议主面板

- Binding：B1、B2、B3、B4、B5。
- Growth：G1、G2、G4。
- Stability：M1、M2、M3。
- Revision：R1、R2、R3、R6。
- Prediction：P1–P3；下游 T1；效率 E1。

采用 A。具体数值阈值在只看 validation 的 R0–R4 pilot 后预注册，随后冻结；主方法不能参与阈值设计。效果量、95% CI、种子数和 failure count 必报。

## 最小 gate 结构

1. Correctness：oracle 全接受，corruption 全命中预期错误码。
2. Safety：B3/B4/M2/R3/G4 不超过冻结上限。
3. Utility：B1/G1/R1/T1 至少一项相对最强公平基线达到冻结效果量，且其余关键项不显著退化。
4. Scalability：E1 与 episode 长度关系在预算内。
