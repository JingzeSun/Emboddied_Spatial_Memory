# HC-033：数据集、场景与切分

状态：BLOCKED_BY_HC-032

## 要决定什么

T1/T2/T3 分别使用什么生成器、模拟器和真实回放数据；怎样保证 scene/layout/appearance 不泄漏。

## 不变量

- 以 scene/layout 为主键切分，不按帧随机切分。
- 同一场景的重渲染和近邻轨迹不跨 train/test。
- pseudo label 与 simulator state 不能伪装成人工 ground truth。

## 选项

| 选项 | 主路线 | 权衡 |
|---|---|---|---|
| A（建议） | 程序化 T1 → 一个交互模拟器 T2 → 一个真实重访/回放 T3 | 能从因果机制逐级扩展到真实噪声 |
| B | 只用大规模模拟器 | 规模足，真实变化与传感器问题不足 |
| C | 只用真实重访数据 | 外部有效性强，动作/region/node oracle 可能不完整 |

## 建议落点

采用 A。具体候选在许可证和字段审查后冻结；不要因为数据集流行就把任务强行改成它已有的标签。若真实数据没有 transaction oracle，只用于 binding/retention 子表，不宣称完整 revision 结果。

## 必须冻结

- scene、room/layout、trajectory 和 appearance 的 split key。
- 动态变化类型及 train/test 组合泛化矩阵。
- region/node/transaction 标注协议与仲裁子集。
- corruption seed、强度范围和生成器 commit。
- 数据排除规则及缺失字段处理。
