# HC-028：节点 latent 状态与更新

状态：BLOCKED_BY_HC-027

## 要决定什么

持久 node 如何保存跨视角 latent，如何吸收新证据而不被单次异常覆写。

## 不变量

- 不把所有历史压成不可审计的单一 EMA。
- 更新只作用于 transaction scope；控制节点不得漂移。
- 原始 evidence 引用必须保留，prototype 可被替换但可追溯。

## 选项

| 选项 | 状态表示 | 权衡 |
|---|---|---|---|
| A（建议） | 有容量上限的 prototype set + reliability/pose/visibility metadata | 支持多视角与异常隔离，成本有界 |
| B | 单一 EMA vector | 快，但容易遗忘和污染，作为旧方法基线 |
| C | 参数化分布/递归状态模型 | 可表达不确定性，但训练与解释复杂 |

## 建议落点

首篇采用 A。每个 persistent node 维护少量视角/结构原型；更新策略可先确定性，再学习 prototype selection。`PredictProject` 从原型及 geometry/relation 生成预期结构 latent，不重建 RGB。

## 写入规则

- `REINFORCE`：增加支持或更新可靠性，不改变事实值。
- `UPDATE`：修改限定 latent/geometry 字段，保留旧版本引用。
- `PRESERVE`：显式不写，仍记录判定 evidence。
- `QUARANTINE`：异常原型不进入 active prototype set。
