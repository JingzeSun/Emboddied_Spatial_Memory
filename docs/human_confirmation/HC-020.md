# HC-020：第一批验证路线

状态：WAITING_USER　｜　阻塞：HC-021–HC-034 的实验落点

## 要决定什么

第一轮先用哪类数据证明任务可执行、强规则会失败，并为 learned binding 建立干净 oracle。

## 不变量

- 不访问正式 test。
- observation region 与 world node 分开标注。
- 每个正例至少四个 deliberate corruptions。
- 第一轮目标是验证研究问题与 evaluator，不是展示大模型分数。

## 选项

| 选项 | 路线 | 优点 | 风险 |
|---|---|---|---|
| A（建议） | 先做 S00–S11 的 T0/T1 小场景，再进一个模拟器 | oracle 清楚，能快速证伪规则与 schema | 早期规模小，不能主张外部有效性 |
| B | 直接 simulator-first | 较早得到具身轨迹与规模 | 错误来源混杂，容易把 simulator 状态泄漏给模型 |
| C | 真实回放 first | 噪声真实 | 标注成本高，难快速定位 identity/birth 定义问题 |

## 建议落点

选 A。先实现 12 个场景族，每族 3–5 个基础 case 和 corruption 变体；P2 通过后只选一个模拟器扩展。真实回放在协议冻结后进入。

## 接受标准

- 两名标注者能独立得到一致 association/transaction。
- evaluator 对 oracle 全接受，对 targeted corruption 命中预期错误码。
- R2/R4 等强规则至少在重复结构、遮挡、动态污染或 pose glitch 中出现可解释失败。
