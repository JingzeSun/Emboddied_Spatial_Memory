# HC-029：Revision transaction 与旧 ESGBU 子模块

状态：BLOCKED_BY_HC-028

## 要决定什么

旧的 operator/scope/temporal/status/evidence 更新如何并入统一 transaction，而不让模型直接任意改图。

## 不变量

- 模型提出 transaction，确定性 executor 检查并执行。
- operation、target、scope、valid time、evidence 缺一不可。
- 历史版本不物理删除；无证据不得填补未知新事实。

## 选项

| 选项 | 解码结构 | 权衡 |
|---|---|---|---|
| A（建议） | 条件分解：association → operation/target → scope → time/evidence | 与决策依赖一致，便于局部 loss 与错误分析 |
| B | 独立多头同时预测全部字段 | 实现快，但组合常不合法，正是旧“改 loss”风险 |
| C | 自回归文本/DSL transaction | 灵活，但格式、约束和小数据稳定性风险高 |

## 建议落点

采用 A。旧 ESGBU 的 `DeltaG/M/tau/Z` 只负责已定位 target 后的 revision 参数，不再承担完整方法。硬不变量由 executor 保证，模型不因 loss penalty 获得绕过权限。

## 操作语义

- CREATE：创建 candidate/confirmed node、edge 或 fact。
- REINFORCE：增加一致证据。
- UPDATE：同一事实的小范围状态修改。
- RELINK：保留 identity，修改关系/位置连接。
- RETRACT：关闭旧事实有效区间。
- REPLACE：RETRACT + 新版本事实的原子组合。
- PRESERVE：证据不足或无需修改。
- QUARANTINE：隔离冲突输入或候选交易。
