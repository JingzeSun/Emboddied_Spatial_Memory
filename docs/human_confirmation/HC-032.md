# HC-032：基线与预算公平性

状态：BLOCKED_BY_HC-031

## 要决定什么

首轮必须实现哪些内部基线，哪些外部系统只做定位或可比实验，以及如何匹配资源。

## 不变量

- 共享可共享的 backbone、proposal、输入字段和训练数据。
- teacher-forced 与 rollout 分开。
- 不把机制近似基线称为官方系统复现。

## 选项

| 选项 | 首轮集合 | 权衡 |
|---|---|---|---|
| A（建议） | R0–R4 + L0/L1 + O0；P4 再加 L2/L3 与可对齐外部系统 | 能尽早判断学习是否必要，成本可控 |
| B | 一开始复现全部外部系统 | 审稿覆盖广，但会延误核心 falsifier |
| C | 只做论文常见 image/graph baseline | 快，但无法排除 pose-warp 和强规则解释 |

## 建议落点

采用 A。主要公平轴为相同前端、相同线上信息、相同 train/validation、相同调参次数；另报告参数匹配与 wall-clock 匹配两张表，不强行把所有方法压成一个预算。

## 必需适配器

- observation adapter：把同一 region/feature 提供给各内部基线。
- memory query adapter：向下游暴露同一只读字段。
- evaluator adapter：统一 node mapping、abstention 和 runtime 计量。
- native external adapter：记录不可对齐字段和官方代码改动。

## 接受测试

每个主结论至少有一个“只少核心机制、其余相同”的近邻基线；性能表同时有参数、训练时长、显存、在线延迟和节点增长。
